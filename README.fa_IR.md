# Guangyue Panel · 广月面板

**یک دامنه. بسته‌ها، نودها و سایت‌ها در یک پنل.**

پنلی خودمیزبان برای مدیریت سرویس‌های پراکسی و منابع شبکه. VLESS Reality/Vision و Hysteria 2 را راه‌اندازی کنید، خروجی‌های IP و سایت‌های مستقل را مدیریت کنید و اشتراک کاربران را بر اساس بسته‌هایشان ارائه دهید. ساخته‌شده با Go و Vue 3؛ نسخهٔ Lite برای یک سایت مستقل و Pro برای مدیریت متمرکز سایت‌ها.

## شروع کار

یک سرور و یک دامنه آماده کنید و نصب‌کننده را اجرا کنید. راهنما نسخه و دامنه را می‌پرسد، محیط را بررسی می‌کند و برنامه، هسته‌های پراکسی، گواهی‌ها و پایگاه دادهٔ لازم را آماده می‌کند. **Docker گزینهٔ پیش‌فرض است؛ نصب مستقیم با systemd نیز قابل انتخاب است.** پنل و نودهای پیش‌فرض می‌توانند از یک دامنه استفاده کنند.

- دامنه باید مستقیماً به سرور شما اشاره کند و **پراکسی CDN خاموش باشد**. در Cloudflare گزینهٔ **DNS only** را انتخاب و ابر نارنجی را خاموش کنید.
- **TCP 443 و UDP 443** باید آزاد باشند و در فایروال سرور و گروه امنیتی سرویس ابری مجاز شوند. نصب‌کننده پورت عمومی دیگری انتخاب نمی‌کند و سرویس HTTPS موجود را تصاحب نمی‌کند.
- سرور کامل Linux با معماری amd64/x86_64 و دسترسی root یا sudo لازم است. پیش‌بررسی Debian 12/13 و Ubuntu 22.04/24.04 را می‌پذیرد؛ تست نصب مستقیم روی ماشین مجازی فعلاً Ubuntu 22.04/24.04 را پوشش می‌دهد. پذیرفته‌شدن سیستم‌عامل به معنی آزمایش همهٔ پیکربندی‌های آن نیست.
- Docker فعلاً فقط IPv4 عمومی دارد: از رکورد A بدون AAAA استفاده کنید. برای IPv6 نصب مستقیم را انتخاب کنید. نقطهٔ شروع پیشنهادی Lite یک هسته و 1 GiB، و Pro دو هسته و 2 GiB است؛ برای داده و پشتیبان فضای بیشتری نگه دارید.

تمام بلوک زیر را در ترمینال سرور کپی کنید:

<div dir="ltr">

```bash
gy_install_file=$(mktemp)
curl --proto '=https' --proto-redir '=https' -fsSL \
  https://github.com/wudi000888-svg/guangyue-panel/releases/latest/download/install.sh \
  -o "$gy_install_file" && sudo bash "$gy_install_file"
rm -f "$gy_install_file"
```

</div>

پیش از نمایش برنامهٔ نصب برای تأیید، DNS، پورت‌ها، منابع و پیکربندی Nginx/Docker بررسی می‌شوند. گواهی از طریق TLS-ALPN-01 روی TCP 443 صادر و تمدید می‌شود؛ پیکربندی موجود Nginx روی HTTP 80 حفظ می‌شود. مؤلفه‌ها و تصاویر Docker از همان نسخهٔ کامل انتخاب‌شده دریافت و با هش‌های آن بررسی می‌شوند.

پس از نصب، از فایل خصوصی حساب اولیه که نصب‌کننده معرفی می‌کند استفاده کنید، رمز مدیر را تغییر دهید و VLESS و HY2 را با کلاینت واقعی آزمایش کنید. ثبت‌نام و عرضهٔ بسته‌ها را پیش از بازکردن سایت برای اعضا تنظیم کنید. ماژول پرداخت سایت مستقل به‌طور پیش‌فرض فعال است، اما کانال‌های پرداخت خارجی به اطلاعات معتبر و پیکربندی نیاز دارند. سایتی که برای نخستین بار به‌عنوان سایت فرعی تحت مدیریت قرار می‌گیرد، به‌طور پیش‌فرض ماژول پرداخت غیرفعال دارد. سایت‌های موجود باید از [به‌روزرسانی و بازگشت نسخه](docs/UPDATES.md) استفاده کنند؛ روی دادهٔ موجود دوباره نصب نکنید. [راهنمای نصب](docs/INSTALL.md) بررسی فقط‌خواندنی با `--check` و ادامهٔ نصب با `--resume` را توضیح می‌دهد.

## انتخاب Lite یا Pro

| | Lite | Pro |
| --- | --- | --- |
| کاربرد اصلی | یک سایت مستقل | سایت اصلی برای مدیریت سایر سایت‌ها |
| دادهٔ پایدار | SQLite | PostgreSQL |
| کش و کارها | کش محدود درون‌فرایندی و صف کار پایدار | Redis و صف کار پایدار |
| اتصال به سایت اصلی | تولید توکن سایت فرعی | تولید توکن هنگام فعالیت به‌عنوان سایت فرعی |
| مدیریت سایت‌های فرعی | ندارد | واردکردن توکن سایت فرعی و مدیریت آن |
| نصب | Docker یا systemd | Docker یا systemd |

هیچ‌کدام به فایل ثبت نیاز ندارند. **سایت فرعی توکن را تولید می‌کند و Pro آن را وارد می‌کند.** توکن می‌تواند تاریخ انقضا داشته باشد یا تا زمان لغو معتبر بماند. سایت متصل مدیر، حساب‌ها، پایگاه داده و سرویس‌های محلی خود را حفظ می‌کند؛ مدیر سایت فرعی می‌تواند دسترسی را لغو کند. [مقایسهٔ نسخه‌ها](docs/EDITIONS.md) و[مدیریت سایت‌ها](docs/BUSINESS-SITES.md) را ببینید.

## قابلیت‌های اصلی

### نودها، خروجی IP و سایت‌های فرعی

نود محلی VLESS Reality/Vision و HY2 اجرا کنید، خروجی HTTP CONNECT یا SOCKS5 اضافه کنید و اشتراک بالادستیِ مجاز را وارد کنید. ورودی منابع عمومی به‌طور پیش‌فرض پنهان است و می‌توان آن را در مرورگر فعلی نمایش داد. این ترجیح نمایشی، جمع‌آوری موجود را متوقف نمی‌کند و دسترسی‌های صادرشده را لغو نمی‌کند.

| منبع | مسیر ترافیک |
| --- | --- |
| **نود متصل‌شدهٔ سایت فرعی** | کلاینت مستقیماً به نود سایت فرعی وصل می‌شود؛ ترافیک از سایت اصلی عبور نمی‌کند. |
| **خروجی IP سایت فرعی** | کلاینت به نود سایت اصلی وصل می‌شود؛ سایت اصلی ترافیک را از خروجی IP سایت فرعی عبور می‌دهد. |

Pro می‌تواند نودهای به‌اشتراک‌گذاشته‌شده را متصل کند، مجوزها را مدیریت کند، نمونه‌های مصرف و تعداد اتصال‌ها را نشان دهد، بودجهٔ مشترک و زمان توقف موقت تعیین کند و به‌روزرسانی سایت‌های فرعیِ پشتیبانی‌شده را بررسی یا کنترل کند. منبع نودهای محلی، فرعی و عمومی مشخص می‌ماند. [اتصال نودها و بودجه](docs/NODE_MOUNTS.md) را ببینید.

### بسته‌ها و اشتراک‌ها

بسته تعیین می‌کند کاربر از کدام نودها استفاده کند. مدیر می‌تواند کل گروه منبع یا نودهای مشخص داخل گروه را انتخاب کند، حجم و اعتبار را تعیین کند و ضریب مصرف نود را برای همان بسته تنظیم کند. کاربر بستهٔ فعلی، زمان و حجم باقی‌مانده، اشتراک و لینک دریافت کلاینت‌های سازگار را می‌بیند.

خرید بسته‌ای متفاوت، شمارش اعتبار باقی‌ماندهٔ بستهٔ قبلی را متوقف می‌کند؛ پس از پایان بستهٔ فعال، اعتبار قبلی مطابق صف از سر گرفته می‌شود. سفارش‌ها، گردش موجودی، کدهای شارژ و بازپرداخت با تأیید مدیر، روندی قابل پیگیری فراهم می‌کنند. بازپرداخت اعتبار فعال بر اساس حجم یا زمان باقی‌مانده محاسبه می‌شود؛ سفارش‌های صف فعلاً مبلغ اصلی همان سفارش را بازمی‌گردانند و ترتیب بازیابی سایر اعتبارها حفظ می‌شود. [بسته‌ها](docs/PLANS.md) و[امور مالی](docs/COMMERCE_EN.md) را ببینید.

### پرداخت، کیف پول و پشتیبانی

برای پرداخت آنلاین EPay V1 یا Stripe Checkout، برای ایمیل SMTP و برای پشتیبانی تیکت قابل تنظیم است. سرویس خارجی به اطلاعات اتصال معتبر و آزمایش عملی نیاز دارد؛ نصب پنل حساب پذیرنده ایجاد نمی‌کند و موفقیت پرداخت واقعی را ثابت نمی‌کند.

با انتخاب روش پرداخت رمزارزی می‌توان برای سفارش آدرس دائمی تخصیص داد. مدیر آدرس‌های دارای موجودی، موجودی شبکه‌های پشتیبانی‌شده و برآورد Gas را می‌بیند و انتقال تجمیعی به مقصد انتخابی را تأیید می‌کند. هزینه فقط پس از تأیید تجمیع توسط مدیر پرداخت می‌شود. پشتیبانی خودکار کارمزد تنها برای آدرس واقعی سفارش با موجودی بیشتر از 0.1 واحد از استیبل‌کوین انتخابیِ مجاز است؛ EVM فقط کسری کارمزد را تأمین می‌کند و Solana از آدرس ثابت پرداخت‌کنندهٔ SOL استفاده می‌کند. اگر هزینه از سقف تأییدشده بیشتر شود، عملیات برای بررسی دستی متوقف می‌شود. کیف پول گرم داخلی از Trust Wallet Core استفاده می‌کند؛ xpub خارجی فقط برای مشاهده است و امکان امضای انتقال ندارد. دریافت و تجمیع خودکار فعلاً Ethereum، BNB Smart Chain، Plasma و Solana را برای دارایی‌های USDT/USDC پشتیبانی‌شده پوشش می‌دهد. وجود تنظیمات L2 به معنی پشتیبانی از تسویه یا تجمیع خودکار آن‌ها نیست. [قواعد خزانهٔ رمزارزی](docs/CRYPTO_TREASURY.md) را بخوانید.

### مدیریت روزانه

رابط محصول به چینی و انگلیسی است و حالت روشن/تاریک، چیدمان موبایل، ناوبری قابل تنظیم، اعلان، بررسی کیفیت نود، محدودیت دسترسی بر اساس کشور، پشتیبان‌گیری و به‌روزرسانی دارد. منبع و زمان نتایج کیفیت و وضعیت نامشخص حفظ می‌شوند. [عملیات](docs/OPERATIONS.md) و[سوابق اعتبارسنجی](docs/VALIDATION.md) دامنهٔ بررسی‌ها را توضیح می‌دهند.

## دامنه و محدودیت‌ها

- دو پروتکل مستقیم VLESS Reality/Vision و Hysteria 2 هستند. واردکردن قالب‌های بالادستی قابلیت جداگانه‌ای است و به پارسر و پشتیبانی Mihomo بستگی دارد.
- فایل‌های نصب فعلی برای Linux amd64 روی سرور کامل systemd هستند؛ Docker فعلاً IPv4 است. ادعای SLA، جابه‌جایی خودکار بین سایت‌ها هنگام خرابی، جداسازی سازمان‌های چندمستاجری یا دسترس‌پذیری بالای چندنمونه‌ای نداریم.
- سرعت ترافیک به هستهٔ پراکسی و مسیر شبکه وابسته است. پایگاه دادهٔ Pro مسیر کند را سریع نمی‌کند؛ آمار مصرف و اتصال نمونه‌برداری می‌شوند و تأخیر محدود دارند.
- تغییر نودها، ضریب‌ها و پروتکل‌های بستهٔ فعال، دسترسی سمت سرور را همگام می‌کند. حجم، مدت اعتبار و اعتبارهای صف، نسخهٔ ثبت‌شده هنگام خرید یا تخصیص را حفظ می‌کنند. کلاینتی که اشتراک قبلی را ذخیره کرده باید آن را تازه کند؛ لغو دسترسی توسط هسته و همگام‌سازی سایت اعمال می‌شود.
- کیف پول گرم را برای **موجودی عملیاتی کم** استفاده کنید؛ پشتیبان را خصوصی نگه دارید و مرتب برداشت کنید. رمزگذاری، اختیار امضا را از سرور پنلِ نفوذشده جدا نمی‌کند. اگر امضای سروری لازم نیست، کلید عمومی خارجی وارد کنید. ادعای ممیزی امنیتی مستقل نداریم.
- RPC عمومی و قیمت بازار ممکن است قطع یا محدود شوند. نتیجهٔ ناموجود یا قدیمی مشخص می‌شود؛ قیمت نمایشی تضمین کارمزد، نرخ تسویه یا پذیرش پرداخت واقعی روی شبکهٔ اصلی نیست.
- دسترسی به صفحهٔ عمومی سرویس استریم یا هوش مصنوعی، دسترسی حساب، پخش محتوا یا حقوق منطقه‌ای را ثابت نمی‌کند. پراکسی عمومی برای ترافیک حساس مناسب نیست.
