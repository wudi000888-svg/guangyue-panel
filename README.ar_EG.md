Guangyue لوحة ذاتية الاستضافة لإدارة خدمات البروكسي وموارد الشبكة، مبنية باستخدام Go و Vue 3. يكفي خادم مناسب ونطاق يشير إليه مسبقًا لتشغيل VLESS Reality/Vision و Hysteria 2، ثم إدارة اشتراكات الباقات وعناوين الخروج والمواقع الفرعية المستقلة والطلبات والتذاكر وتحصيل المدفوعات من داخل اللوحة.

تناسب اللوحة مشغّلي خدمات البروكسي الذين يبدؤون بموقع واحد، والمسؤولين الذين يحتاجون إلى إدارة عدة مواقع مستقلة مركزيًا، والفرق التي تخصّص عناوين خروج لأعضائها. إصدار Lite للتشغيل المستقل، ويوسّعه Pro إلى لوحة تحكم لموقع رئيسي. يُثبَّت الإصداران بالسكربت التفاعلي نفسه.

## ابدأ هنا

### قبل التثبيت

- **يجب أن يشير النطاق مسبقًا إلى هذا الخادم دون تفعيل بروكسي CDN.** في Cloudflare اختر «DNS only» وأوقف السحابة البرتقالية.
- استخدم **خادم Linux amd64 (x86_64) كاملًا يعمل بـ systemd** مع صلاحية root / sudo. يقبل الفحص المسبق Debian 12/13 و Ubuntu 22.04/24.04، وتغطي اختبارات التثبيت الأصلي على الآلات الافتراضية حاليًا Ubuntu 22.04/24.04. قبول النظام لا يعني أن جميع إعدادات الخوادم قد اختُبرت.
- **يجب أن يكون المنفذان العامّان TCP 443 و UDP 443 غير مستخدمين ومسموحين**، في مجموعة الأمان السحابية وجدار حماية الخادم معًا. يستخدم السكربت المنفذ 443 دائمًا ولا ينقل خدمة HTTPS موجودة، ويمكن الإبقاء على خدمة Nginx الحالية على HTTP 80.
- **Docker هو الخيار الافتراضي، والتثبيت الأصلي اختياري.** ينشر Docker حاليًا عبر IPv4 فقط، لذا اضبط سجلات A فقط دون AAAA، واختر التثبيت الأصلي ثنائي المكدّس إذا احتجت إلى IPv6. يتطلب Docker نظام Linux 5.4 أو أحدث.
- نقترح البدء بـ 1 CPU / 1 GiB لإصدار Lite و 2 CPU / 2 GiB لإصدار Pro، مع ترك مساحة للصور والبيانات والنسخ الاحتياطية. هذه توصية للتثبيت، وليست وعدًا بعدد مستخدمين متزامنين أو بعرض نطاق محدد.

### تشغيل سكربت التثبيت

انسخ الكتلة التالية كاملةً إلى طرفية الخادم:

<div dir="ltr">

```bash
gy_install_file=$(mktemp)
curl --proto '=https' --proto-redir '=https' -fsSL \
  https://github.com/wudi000888-svg/guangyue-panel/releases/latest/download/install.sh \
  -o "$gy_install_file" && sudo bash "$gy_install_file"
rm -f "$gy_install_file"
```

</div>

يطلب منك المعالج اختيار Lite أو Pro والنطاق وطريقة النشر، ثم يفحص النظام والموارد و DNS والمنافذ وأي إعدادات Nginx / Docker موجودة، ويعرض خطة التثبيت لتأكيدها. تأتي المكوّنات وصور Docker من الإصدار المختار وتُتحقَّق بمجاميعه الاختبارية، ولا حاجة إلى حساب في سجل الصور. تُصدَر الشهادات وتُجدَّد تلقائيًا عبر TLS-ALPN-01 على TCP 443.

بعد التثبيت، اقرأ ملف الحساب الأولي الخاص `/var/lib/guangyue/initial-owner.json` كما يرشدك السكربت، وسجّل الدخول وغيّر كلمة مرور المسؤول، ثم اختبر VLESS و HY2 بعميل حقيقي. اضبط التسجيل وعرض الباقات وقنوات التحصيل حسب الحاجة؛ تتطلب خدمات الدفع والبريد الخارجية إعدادات صالحة خاصة بك.

ينفّذ `--check` فحصًا مسبقًا للقراءة فقط، ويستأنف `--resume` تثبيتًا متوقفًا. على المواقع القائمة استخدام [التحديث والرجوع عبر الإنترنت](docs/UPDATES.md) بدلًا من تثبيت جديد فوق بياناتها. تجد المتطلبات الكاملة والاستعادة بعد الفشل وحدود النشر في [دليل التثبيت](docs/INSTALL.md).

## Lite أم Pro؟

| | Lite | Pro |
| --- | --- | --- |
| الاستخدام الافتراضي | موقع مستقل، ويمكن أن يكون موقعًا فرعيًا | موقع رئيسي يدير المواقع الفرعية مركزيًا |
| قاعدة البيانات | SQLite | PostgreSQL |
| التخزين المؤقت والمهام | ذاكرة مؤقتة محدودة داخل العملية، وطابور مهام دائم | ذاكرة Redis المؤقتة، وطابور مهام دائم |
| وظائف الموقع | العُقد ومجمّع IP والباقات والمستخدمون والطلبات والتذاكر | مثل Lite مع إضافة الإدارة المركزية |
| طريقة الربط | يولّد رمز موقع فرعي ليستورده الموقع الرئيسي | الصق رمز الموقع الفرعي لإنشاء الاتصال |
| طريقة التثبيت | Docker / systemd أصلي | Docker / systemd أصلي |

لا يحتاج التثبيت إلى ملف تسجيل ولا إلى إنشاء مجموعات مواقع مسبقًا. **يولّد الموقع الفرعي الرمز، ويلصقه موقع Pro الرئيسي.** يمكن أن تكون للرمز مدة صلاحية أو أن يبقى صالحًا حتى إلغائه. يحتفظ الموقع الفرعي بعد الربط بمسؤوليه المحليين وحساباته وقاعدة بياناته وخدماته المستقلة، ويمكن إلغاء التفويض. عندما يُدار موقع فرعي لأول مرة تكون وحدة الدفع فيه معطّلة افتراضيًا، ويمكن لمسؤوله المحلي تفعيلها عند الحاجة. راجع [الفروق بين الإصدارات](docs/EDITIONS.md) و[إدارة المواقع الفرعية](docs/BUSINESS-SITES.md).

### الباقة تحدد العُقد التي يستخدمها الأعضاء

يختار المسؤول للباقة مجموعات عُقد محلية أو فرعية أو عامة، أو عُقدًا محددة داخل مجموعة. يرى الأعضاء باقتهم الحالية والوقت والحصة المتبقيين ومدخل الاشتراك والعملاء، دون الحاجة إلى فهم مجموعات العُقد أو القواعد الداخلية للاشتراكات المختلطة.

عند شراء باقة أخرى تتوقف الصلاحية المتبقية للباقة الحالية، ثم تُستأنف حسب طابور الاستحقاقات. يتطلب الاسترداد مراجعة المسؤول: تُحسب الباقة الحالية حسب الحصة أو الوقت المتبقي، وتعيد الطلبات المنتظرة حاليًا مبلغ الطلب الأصلي، ويُحفظ ترتيب استعادة الاستحقاقات الأخرى. القواعد الدقيقة في [الباقات](docs/PLANS.md) و[الطلبات والاسترداد](docs/COMMERCE_EN.md). تتزامن تعديلات العُقد والمعاملات والبروتوكولات في الباقة الحالية مع تفويض الخادم، بينما تحتفظ الحصة ومدة الصلاحية والباقات المنتظرة بلقطتها. ولا يزال على العميل تحديث الاشتراك المخزّن لديه.

### عُقد الموقع الفرعي وعناوين IP الخاصة به مساران مختلفان

- **عُقد الموقع الفرعي المركّبة:** يتصل العميل مباشرةً بعقدة الموقع الفرعي، ولا تمر الحركة عبر الموقع الرئيسي.
- **مخارج IP للموقع الفرعي:** يتصل العميل بعقدة في الموقع الرئيسي، ويمرّر الموقع الرئيسي الحركة عبر مخرج IP التابع للموقع الفرعي.

يُدار النوعان بشكل منفصل ويُوسمان بمصدرهما. عند نفاد الميزانية المشتركة لموقع فرعي يُعلَّق التفويض حسب الإعدادات ويعود بعد انتهاء فترة التهدئة، مع الحفاظ على عضوية مجموعات العُقد. خطوات الإعداد في [تركيب العُقد والميزانيات](docs/NODE_MOUNTS.md).

### تحصيل العملات المشفرة والمحافظ

عندما يختار المستخدم الدفع بالعملات المشفرة يُخصَّص للطلب عنوان مستقل يُحفظ بشكل دائم. يغطي التحصيل والتجميع التلقائيان حاليًا أصول USDT / USDC المدعومة على Ethereum و BNB Smart Chain و Plasma و Solana، وفق القائمة المسموح بها من العقود أو mint؛ ولا يعني ضبط شبكة L2 أنها تدعم التسوية والتجميع التلقائيين.

استعلامات الرصيد و Gas للقراءة فقط. **لا تُدفع الرسوم إلا عندما يؤكد المسؤول التجميع.** يقتصر الدعم التلقائي للرسوم على عناوين الطلبات الحقيقية التي يزيد فيها رصيد العملة المستقرة المختارة من القائمة المسموح بها على 0.1 زيادةً صريحة. في EVM يُغطّى الفرق الناقص فقط، وفي Solana تُدفع الرسوم من عنوان تمويل SOL ثابت. وإذا كان سيُتجاوز سقف الرسوم الموافق عليه أصلًا، تتوقف العملية للمراجعة اليدوية. التفاصيل والفروق بين الشبكات في [إدارة المحافظ](docs/CRYPTO_WALLETS.md) و[تحصيل الطلبات وتجميعها](docs/CRYPTO_TREASURY.md).

المحفظة الساخنة المدمجة مناسبة للأرصدة التشغيلية الصغيرة. ورغم أن عبارة الاسترداد تُخزَّن مشفّرة، تبقى صلاحية التوقيع على الخادم نفسه؛ احتفظ بنسخة احتياطية خاصة واسحب الأموال بانتظام. يمكن استخدام xpub خارجي لشبكات EVM لاشتقاق العناوين والاستعلام عنها، بينما تُنفَّذ التحويلات من المحفظة الخارجية؛ ولا يمنح ذلك الخادم قدرة على التوقيع.

## النطاق والحدود

- بروتوكولات الدخول المقدّمة مباشرةً هي **VLESS Reality/Vision و Hysteria 2**. تعتمد صيغ المصادر القابلة للاستيراد على المحلّل و Mihomo، ولا تضيف مداخل أصلية بالاسم نفسه.
- النشر الحالي هو وحدة تحكم واحدة لكل موقع. لا نَعِد بتوافر عالٍ متعدد الخوادم الرئيسية للموقع الواحد، أو عزل المستأجرين على مستوى المؤسسات، أو SLA، أو تدقيق أمني مستقل. ولا تحسّن قاعدة بيانات Pro وذاكرته المؤقتة مسار شبكة مزدحمًا بطبيعته.
- يشمل CI تثبيتًا معزولًا على Linux واستعادة التحديث والتحقق من البروتوكولات. هذا ليس تقرير سعة لإنتاج واسع النطاق، ولا قبولًا لحساب التاجر الخاص بك أو لمعاملات الشبكة الرئيسية. قبل الإطلاق اختبر العملاء الحقيقيين والنسخ الاحتياطية والبريد ومسارات الدفع.
- قد تكون مصادر RPC والأسعار وفحوص الجودة محدودة أو غير متاحة. لا تُعامَل النتيجة المجهولة أبدًا كرسوم صفرية، والوصول إلى صفحة عامة لا يعني أن الحسابات أو التشغيل أو المدفوعات أو الخدمات الإقليمية متاحة كلها.
- يقدّم هذا المستودع **تعريفًا بالمشروع بـ 7 لغات**؛ وتدعم واجهة اللوحة حاليًا **الصينية المبسطة والإنجليزية**. الأدلة التفصيلية بالصينية في الغالب، وبعضها بالإنجليزية؛ ولا يعني التعريف المترجم أن الواجهة والأدلة مترجمة إلى تلك اللغة.
