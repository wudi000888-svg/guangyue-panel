# Guangyue Panel · 广月面板

**نطاق واحد. الباقات والعُقد والمواقع في لوحة واحدة.**

لوحة ذاتية الاستضافة لإدارة خدمات البروكسي وموارد الشبكة. شغّل VLESS Reality/Vision و Hysteria 2، وأدر عناوين الخروج والمواقع المستقلة، ووزّع الاشتراكات وفق باقات المستخدمين. مبنية باستخدام Go و Vue 3؛ إصدار Lite لموقع مستقل، وإصدار Pro للإدارة المركزية للمواقع.

## ابدأ هنا

جهّز خادمًا ونطاقًا، ثم شغّل المثبّت. يطلب المعالج الإصدار والنطاق، ويفحص البيئة، ثم يجهّز التطبيق وأنوية البروكسي والشهادات وقاعدة البيانات المطلوبة. **Docker هو الخيار الافتراضي، ويمكن اختيار التثبيت الأصلي باستخدام systemd.** تستطيع اللوحة والعُقد الافتراضية مشاركة نطاق واحد.

- وجّه النطاق مباشرةً إلى الخادم و**عطّل بروكسي CDN**. في Cloudflare اختر **DNS only** وأوقف السحابة البرتقالية.
- يجب أن يكون المنفذان **TCP 443 و UDP 443** متاحين ومسموحين في جدار الحماية ومجموعة الأمان السحابية. لا يختار المثبّت منفذًا عامًا آخر ولا يستولي على خدمة HTTPS موجودة.
- استخدم خادم Linux كاملًا بمعمارية amd64/x86_64 وصلاحية root أو sudo. الفحص المسبق يقبل Debian 12/13 و Ubuntu 22.04/24.04؛ اختبارات التثبيت الأصلي على آلات افتراضية تغطي حاليًا Ubuntu 22.04/24.04. قبول النظام لا يعني اختبار جميع إعداداته.
- Docker ينشر على IPv4 فقط حاليًا: استخدم سجلات A دون AAAA. اختر التثبيت الأصلي إذا احتجت IPv6. نقطة البداية المقترحة: نواة واحدة و 1 GiB لـLite، أو نواتان و 2 GiB لـPro، مع مساحة إضافية للبيانات والنسخ الاحتياطية.

انسخ الكتلة التالية كاملةً إلى طرفية الخادم:

<div dir="ltr">

```bash
gy_install_file=$(mktemp)
curl --proto '=https' --proto-redir '=https' -fsSL \
  https://github.com/wudi000888-svg/guangyue-panel/releases/latest/download/install.sh \
  -o "$gy_install_file" && sudo bash "$gy_install_file"
rm -f "$gy_install_file"
```

</div>

يفحص المثبّت DNS والمنافذ والموارد وإعدادات Nginx/Docker قبل عرض خطة للتأكيد. تُصدر الشهادات وتُجدّد عبر TLS-ALPN-01 على TCP 443؛ تبقى إعدادات Nginx الحالية على HTTP 80 محفوظة. مكونات التشغيل وصور Docker تأتي من الإصدار الكامل المحدد وتُفحص قيمها التجزئية.

بعد التثبيت، استخدم ملف الحساب الأولي الخاص الذي يحدده المثبّت، وغيّر كلمة مرور المدير، ثم اختبر VLESS و HY2 بعميل حقيقي. اضبط التسجيل وعروض الباقات قبل فتح الموقع للأعضاء. وحدة الدفع مفعّلة افتراضيًا للمواقع المستقلة، لكن قنوات الدفع الخارجية تحتاج بيانات اعتماد صالحة وإعدادًا. الموقع الذي يُضمّ لأول مرة كموقع فرعي مُدار تكون وحدة الدفع فيه معطّلة افتراضيًا. للمواقع الموجودة، اتبع [التحديث والتراجع](docs/UPDATES.md) بدل إعادة التثبيت فوق البيانات. يشرح [دليل التثبيت](docs/INSTALL.md) الفحص للقراءة فقط عبر `--check` واستكمال التثبيت عبر `--resume`.

## Lite أم Pro؟

| | Lite | Pro |
| --- | --- | --- |
| الاستخدام الأساسي | موقع يعمل بصورة مستقلة | موقع رئيسي يدير مواقع أخرى |
| قاعدة البيانات | SQLite | PostgreSQL |
| التخزين المؤقت والمهام | ذاكرة مؤقتة محدودة داخل العملية وطابور مهام دائم | Redis وطابور مهام دائم |
| الاتصال بموقع رئيسي | إنشاء رمز موقع فرعي | إنشاء رمز عند العمل كموقع فرعي |
| إدارة المواقع الفرعية | غير متاحة | استيراد رمز الموقع الفرعي وإدارته |
| التثبيت | Docker أو systemd | Docker أو systemd |

لا يحتاج أي إصدار إلى ملف تسجيل. **الموقع الفرعي ينشئ الرمز، و Pro يستورده.** يمكن تحديد تاريخ انتهاء أو إبقاء الرمز صالحًا حتى إلغائه. تحتفظ المواقع المتصلة بمديريها وحساباتها وقواعد بياناتها وخدماتها المحلية؛ ويمكن لمدير الموقع الفرعي إلغاء الوصول. راجع [الإصدارات](docs/EDITIONS.md) و[إدارة المواقع](docs/BUSINESS-SITES.md).

## الوظائف الأساسية

### العُقد وعناوين الخروج والمواقع الفرعية

شغّل عُقد VLESS Reality/Vision و HY2 المحلية، وأضف مخارج HTTP CONNECT أو SOCKS5، واستورد اشتراكات المنبع التي تملك حق استخدامها. مداخل الموارد العامة مخفية افتراضيًا ويمكن إظهارها في المتصفح الحالي. هذا التفضيل المرئي لا يوقف عمليات الجمع الموجودة ولا يلغي صلاحيات سبق إصدارها.

| المورد | مسار حركة المرور |
| --- | --- |
| **عُقد الموقع الفرعي المضافة** | يتصل العميل مباشرةً بالموقع الفرعي؛ لا تمر الحركة عبر الموقع الرئيسي. |
| **مخارج IP للموقع الفرعي** | يتصل العميل بعقدة الموقع الرئيسي، ثم تُمرّر الحركة عبر عنوان خروج الموقع الفرعي. |

يتيح Pro إضافة العُقد المشتركة، وإدارة الصلاحيات، وعرض عينات الاستخدام وعدد الاتصالات، وتحديد ميزانيات مشتركة وفترات تهدئة، وفحص أو التحكم بتحديث المواقع الفرعية المدعومة. يبقى مصدر العُقد المحلية والفرعية والعامة واضحًا. راجع [إضافة العُقد والميزانيات](docs/NODE_MOUNTS.md).

### الباقات والاشتراكات

تحدد الباقة العُقد التي يمكن للعضو استخدامها. يستطيع المدير اختيار مجموعات مصادر كاملة أو عُقد محددة داخل المجموعة، وضبط الحصة والصلاحية ومعامل احتساب حركة العقدة داخل الباقة. يرى العضو باقته الحالية والوقت والحصة المتبقيين والاشتراك وروابط تنزيل العملاء المتوافقين.

شراء باقة مختلفة يوقف حساب الوقت المتبقي للباقة السابقة؛ تستأنف الاستحقاقات السابقة حسب الطابور عندما تنتهي الباقة النشطة. الطلبات وسجل الرصيد ورموز الشحن وطلبات الاسترداد الخاضعة لموافقة المدير تدعم سير عمل قابلًا للتتبع. تُحسب مبالغ استرداد الاستحقاق النشط حسب الحصة أو الوقت المتبقي؛ وتُعيد الطلبات المنتظرة حاليًا مبلغ الطلب الأصلي مع الحفاظ على ترتيب استعادة الاستحقاقات الأخرى. راجع [الباقات](docs/PLANS.md) و[المعاملات](docs/COMMERCE_EN.md).

### الدفع والمحافظ والدعم

يدعم التكامل EPay V1 و Stripe Checkout للدفع، و SMTP للبريد، والتذاكر لدعم الأعضاء. هذه الخدمات تحتاج بيانات اعتماد صالحة واختبارات فعلية؛ التثبيت لا ينشئ حساب تاجر ولا يثبت نجاح الدفع الحقيقي.

عند اختيار الدفع بالعملات المشفرة يمكن تخصيص عنوان دائم للطلب. يستطيع المدير عرض العناوين ذات الرصيد وأرصدة الشبكات المدعومة وتقديرات Gas، ثم الموافقة على تجميع الأموال إلى وجهة يحددها. لا تُدفع الرسوم إلا بعد موافقة المدير على التجميع. دعم الرسوم التلقائي يتطلب عنوان طلب حقيقيًا برصيد يزيد عن 0.1 من العملة المستقرة المختارة والمسموح بها. في EVM يُموَّل النقص فقط؛ وفي Solana يدفع عنوان SOL الثابت الرسوم. تجاوز سقف الرسوم المعتمد يوقف العمليات للمراجعة اليدوية. المحفظة الساخنة المدمجة تستخدم Trust Wallet Core؛ استيراد xpub الخارجي يسمح بالمراقبة ولا يسمح بتوقيع التحويلات. التحصيل والتجميع التلقائيان يغطيان حاليًا Ethereum و BNB Smart Chain و Plasma و Solana لأصول USDT/USDC المدعومة. وجود إعدادات L2 لا يعني دعم التسوية أو التجميع التلقائي عليها. راجع [قواعد إدارة الأموال](docs/CRYPTO_TREASURY.md).

### التشغيل اليومي

واجهة المنتج متاحة بالصينية والإنجليزية، مع الوضعين الفاتح والداكن وتخطيط الهاتف والتنقل القابل للتخصيص والإشعارات وفحص جودة العُقد وقواعد الوصول حسب الدولة والنسخ الاحتياطي والتحديثات. تبقى مصادر نتائج الجودة وأوقاتها وحالات تعذر القراءة ظاهرة. راجع [التشغيل](docs/OPERATIONS.md) و[سجلات التحقق](docs/VALIDATION.md).

## النطاق والحدود

- بروتوكولا الاتصال المباشر هما VLESS Reality/Vision و Hysteria 2. استيراد بروتوكولات المنبع قدرة منفصلة تعتمد على المحلل ودعم Mihomo.
- ملفات التثبيت الحالية تستهدف Linux amd64 على خوادم كاملة تستخدم systemd؛ Docker حاليًا IPv4 فقط. لا توجد مطالبة بـSLA أو تجاوز فشل تلقائي بين المواقع أو عزل مؤسسات متعددة أو توافر عالٍ متعدد النسخ.
- سرعة المرور تعتمد على أنوية البروكسي ومسارات الشبكة. قاعدة بيانات Pro لا تسرّع خطًا بطيئًا؛ الاستخدام والاتصالات يُعرضان بعينات مع تأخر محدود.
- تغييرات عُقد الباقة النشطة ومعاملاتها وبروتوكولاتها تزامن صلاحيات الخادم. تحتفظ الحصة والصلاحية والاستحقاقات المنتظرة بنسخها المسجلة عند الشراء أو التخصيص. العميل الذي يحتفظ باشتراك قديم يحتاج تحديثه؛ إلغاء الصلاحيات تنفذه الأنوية ومزامنة الموقع.
- استخدم المحافظ الساخنة **لأرصدة تشغيل صغيرة**، واحتفظ بنسخ خاصة واسحب الأموال دوريًا. التشفير لا يفصل سلطة التوقيع عن خادم لوحة مخترق. استخدم المفتاح العام الخارجي عند عدم الحاجة للتوقيع على الخادم. لا ندّعي تدقيقًا أمنيًا مستقلًا.
- قد تتعطل خدمات RPC العامة وأسعار السوق أو تُقيَّد طلباتها. النتائج المفقودة أو القديمة تُعرض كغير متاحة؛ السعر المعروض ليس رسومًا مضمونة أو إثباتًا لاختبار أموال حقيقية على الشبكة الرئيسية.
- الوصول إلى الصفحة العامة لخدمة بث أو ذكاء اصطناعي لا يثبت حق الحساب أو تشغيل المحتوى أو الوصول الإقليمي. البروكسيات العامة لا تناسب الحركة الحساسة.
