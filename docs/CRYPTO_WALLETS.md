# 加密钱包与地址管理

管理员在“系统设置 → 交易与接入”管理加密钱包。当前支持内置热 HD 钱包、外部 xpub、手动地址分配、停用、备份和恢复。**这些功能不代表链上支付已开通**：当前没有主网扫描器、USDT/USDC 自动认款、加密货币套餐支付或自动归集，也不会把手动地址当作已付款订单。

## 选择钱包方式

| 方式 | 面板保存什么 | 适合谁 |
| --- | --- | --- |
| 内置热钱包 | Vault 加密的助记词、公开分支配置和地址分配记录 | 希望在面板内创建和备份钱包的管理员；只存小额并定期转走 |
| 外部 xpub | 专用 EVM 收款分支扩展公钥、路径和分配记录；不保存助记词 | 已有可导出兼容分支 xpub 的外部钱包/签名工具，并能从对应路径转出资金的管理员 |

内置钱包由官方 `@trustwallet/wallet-core@4.8.4` 浏览器 WASM 创建，使用标准 24 个助记词。约 10.39 MB 的官方 WASM 在需要钱包功能时按需加载，资源随安装包从本站提供，无 CDN，也无需服务器运行 Node 或钱包侧车服务。Go 独立校验助记词与公钥、执行 BIP-32 只读派生；标准 12/24 词均可校验，本期不支持额外 BIP-39 passphrase。

这不是连接或读取现有 OKX 钱包，不会取得 OKX 的私钥。普通地址和钱包连接签名也不能替代 xpub。外部 xpub 必须来自你控制且支持相同 EVM 派生路径的钱包，不能仅凭“能生成地址”判断其中的资金可转出。

## 创建和备份内置钱包

1. 选择内置热钱包并设置名称，按提示验证当前管理员密码。浏览器生成助记词和分支公钥，后端独立核对后加密保存。
2. 使用独立备份口令下载钱包备份文件。口令至少 12 个字符，且不能与当前管理员密码相同。
3. 将备份文件和口令分别妥善保存，然后确认已保存备份。未确认备份的热钱包不能继续分配地址。
4. 在钱包详情分配手动地址，核对网络和派生路径。地址生成会永久记录索引，不因刷新或停用而回收。

备份采用 `guangyue-crypto-wallet-v1` 格式，包含钱包身份、助记词、分支、索引高水位及地址分配记录；使用 scrypt（N=32768、r=8、p=1）和 AES-256-GCM，以随机盐和 nonce 加密。该文件可用独立备份口令恢复，不依赖原服务器的 `master.key`。服务端不能找回丢失的独立备份口令。

可移植钱包备份最多包含 30,000 条地址记录，内部明文上限 8 MiB；超出时使用完整面板备份。加密文件因编码会更大。为保护 Lite 内存，同一面板一次处理一个备份/恢复任务；等待超过 5 秒会提示稍后重试。恢复由服务端解密并独立验证钱包材料，浏览器不重新生成钱包。

普通钱包列表、审计日志和通知不包含助记词。需要在外部钱包手动转出时，可在敏感查看流程再次输入当前管理员密码，临时查看助记词；操作结束关闭窗口。不要把助记词复制到工单、聊天、日志或网页 URL。当前没有面板内广播交易与自动归集流程，转出前在兼容的外部工具核对网络、派生路径、完整已分配索引及手续费资产。

## 停用与恢复

停用仅阻止继续分配地址；钱包、历史地址和加密材料仍然保留。已有链上资产不会因为停用而转走。

恢复入口接受完整的加密钱包备份，不提供只输入助记词就从索引 0 重新发地址的流程。恢复到已有相同分支的本站钱包时，保留原有地址，并取当前与备份中更高的分配索引。恢复到新站时，钱包进入暂停和“需要核对恢复进度”状态，必须先完成以下步骤：

1. 停止旧站继续为该分支分配地址，确认不会有两个面板同时使用同一个分支。
2. 核对旧站最新分配记录；填入下一可用索引，至少为历史最高已用索引加 1，且不得低于导入备份的高水位。
3. 明确确认核对完成，再单独启用新地址分配。仅完成备份导入不会自动启用。

旧备份不知道备份之后用过的地址。面板不能仅凭旧文件保证跨部署不重复；无法查清最新索引时保持暂停，先保全原库和记录。不要通过删除钱包、换显示名称、从索引 0 重建或同时运行两份数据库绕过核对。外部钱包的默认 gap limit 也可能漏掉较大索引处的资金，迁移时要保留完整地址记录。

## 服务器与密钥保全

内置热钱包的加密材料仍由面板服务器托管；有权读取运行中的进程、数据库和解密密钥的人可能获得钱包控制权。只存小额，并按自己的运营计划定期转出到其他钱包。

面板完整备份需要同时保全数据库和**对应的 `master.key`**；只有数据库中的密文不足以解密热钱包。独立钱包备份作为另一条恢复路径，其文件和口令也要保全。不要把数据库、`master.key` 与备份口令一起上传到公共位置。恢复旧面板快照后仍须核对快照之后的地址高水位，不能据“完整快照恢复成功”推断地址从未被使用。

敏感 API 仅限本站 owner，验证当前管理员密码，拒绝子站代理身份；响应 `no-store`。助记词不进入 URL、浏览器 localStorage/sessionStorage、普通幂等缓存或日志。前端页面能正确运行 WASM、后端能派生地址和备份能解密，分别是钱包管理验证，不是主网收款或资金转出验收。
