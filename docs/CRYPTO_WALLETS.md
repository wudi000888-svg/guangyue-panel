# 加密钱包与地址管理

管理员在独立“加密货币”模块管理钱包，默认查看全部钱包资产：桌面瀑布卡片，手机单列。当前支持内置热 HD 钱包、助记词导入、外部 xpub、停用、永久删除、加密备份和钱包备份导入；配置链上支付后，用户选择加密付款时自动分配地址，无需管理员逐单操作。Ethereum/BSC 的白名单 USDT/USDC 最终确认后自动认款并开通套餐。内置热钱包可使用固定 Gas 地址和管理员发起的提取任务；外部 xpub 保持只读。实际配置、余额和资金操作见[订单与归集](CRYPTO_TREASURY.md)。

## 选择钱包方式

| 方式 | 面板保存什么 | 适合谁 |
| --- | --- | --- |
| 内置热钱包 | Vault 加密的助记词、公开分支配置和地址分配记录 | 希望在面板内创建和备份钱包的管理员；只存小额并定期转走 |
| 外部 xpub | 专用 EVM 收款分支扩展公钥、路径和分配记录；不保存助记词 | 已有可导出兼容分支 xpub 的外部钱包/签名工具，并能从对应路径转出资金的管理员 |

内置钱包由官方 `@trustwallet/wallet-core@4.8.4` 浏览器 WASM 创建，使用标准 24 个助记词。约 10.39 MB 的官方 WASM 在需要钱包功能时按需加载，资源随安装包从本站提供，无 CDN，也无需服务器运行 Node 或钱包侧车服务。Go 独立校验助记词与公钥、执行 BIP-32 只读派生；标准 12/24 词均可校验，本期不支持额外 BIP-39 passphrase。

这不是连接或读取现有 OKX 钱包，不会取得 OKX 的私钥。普通地址和钱包连接签名也不能替代 xpub。外部 xpub 必须来自你控制且支持相同 EVM 派生路径的钱包，不能仅凭“能生成地址”判断其中的资金可转出。

## 创建和备份内置钱包

1. 选择内置热钱包并设置名称及支持网络（默认 BNB Smart Chain，可选 Ethereum），按提示验证当前管理员密码。浏览器生成助记词和分支公钥，后端独立核对后加密保存。
2. 使用独立备份口令下载钱包备份文件。口令至少 12 个字符，且不能与当前管理员密码相同。
3. 将备份文件和口令分别妥善保存，然后确认已保存备份。未确认备份的热钱包不能继续分配地址。
4. 在链上支付设置中选择钱包、网络及 USDT/USDC，输入管理员密码后“一键启用”。面板内置双独立公共 RPC 和自动报价，完整预检通过才启用；高级配置仍可手动覆盖。用户选择加密付款时自动分配地址，地址和订单记录不会因刷新、到期、取消或停用而回收。原有手动地址工具作为管理员可选工具保留。

创建成功立即返回固定 Gas 地址及派生路径，不依赖 RPC 查询或第一笔订单。只显示创建时选择的网络；BNB-only 钱包只提示在 BNB Smart Chain 充 BNB，不能用其他链 ETH 支付其手续费。各 EVM 网络地址字符串可能相同，但余额独立，界面选链不能阻止他人向其他网络误转。新钱包不提供后续编辑支持网络的入口；历史钱包迁移默认保留 Ethereum/BNB。

备份采用 `guangyue-crypto-wallet-v1` 格式，包含钱包身份、助记词、分支、支持网络、固定 Gas 描述、索引高水位及地址分配记录；使用 scrypt（N=32768、r=8、p=1）和 AES-256-GCM，以随机盐和 nonce 加密。该文件可用独立备份口令恢复，不依赖原服务器的 `master.key`。服务端不能找回丢失的独立备份口令。

可移植钱包备份最多包含 30,000 条地址记录，内部明文上限 8 MiB；超出时使用完整面板备份。加密文件因编码会更大。为保护 Lite 内存，同一面板一次处理一个备份/恢复任务；等待超过 5 秒会提示稍后重试。恢复由服务端解密并独立验证钱包材料，浏览器不重新生成钱包。

永久删除后通过外部材料导入的同分支新钱包，可在当前面板查看旧地址资产；它的便携备份只含新 ID 的地址记录及完整索引高水位。迁往全新面板时，旧 ID 地址的展示仍需原公共历史或原备份；便携钱包备份不能替代完整面板历史备份。

普通钱包列表、审计日志和通知不包含助记词。内置热钱包可以在余额与提取页面指定目标地址、资产和阈值，查看自动估算并冻结的费用上限，经当前管理员密码确认后由后台补足 Gas 并执行归集。不需要把助记词导入客户端或逐地址签名。需要在外部钱包手动转出时，可在敏感查看流程临时查看助记词，并核对完整派生路径和索引；操作结束关闭窗口。不要把助记词复制到工单、聊天、日志或网页 URL。

## 停用、永久删除与导入

停用仅阻止继续分配地址；钱包、历史地址和加密材料仍然保留。已有链上资产不会因为停用而转走。

永久删除需要管理员密码、钱包版本核对和不可撤销确认。删除会清除面板中的钱包实体与加密助记词，并停止该钱包的新收款配置。旧版已软删除的钱包在升级时直接清理。面板没有已删除钱包列表或撤销入口；原钱包 ID 的加密备份不能恢复已永久删除的钱包。

历史订单、公开地址占用、派生索引高水位、链上事件去重和资金任务记录保留，供旧付款核对和防止重复使用。删除不会自动转走链上资金，没有外部助记词可能失去后续提取能力。管理员自己保管的外部助记词、离线文件或整机快照属于独立恢复材料，面板不会擦除这些副本。未结束的提取任务须先解决。

助记词导入使用 12/24 个英文词，不支持附加 BIP-39 passphrase。导入创建新钱包 ID，保持暂停并要求核对恢复进度。本站已有同分支历史时，下一索引不得低于历史最高已用索引加一，旧地址不会重新发给新订单；同分支的历史资产可查询及按明确授权归集，原订单归属保持稳定。

加密钱包备份导入保留钱包身份、地址记录和分配索引。对未永久删除的已有同分支钱包，使用当前与备份中更高的分配索引。新站导入助记词或备份后，必须先完成以下步骤：

1. 停止旧站继续为该分支分配地址，确认不会有两个面板同时使用同一个分支。
2. 核对旧站最新分配记录；填入下一可用索引，至少为历史最高已用索引加 1，且不得低于导入备份的高水位。
3. 明确确认核对完成，再单独启用新地址分配。仅完成备份导入不会自动启用。

旧备份不知道备份之后用过的地址。面板不能仅凭旧文件保证跨部署不重复；无法查清最新索引时保持暂停，先保全原库和记录。不要通过删除钱包、换显示名称、从索引 0 重建或同时运行两份数据库绕过核对。外部钱包的默认 gap limit 也可能漏掉较大索引处的资金，迁移时要保留完整地址记录。

## 服务器与密钥保全

内置热钱包的加密材料仍由面板服务器托管；有权读取运行中的进程、数据库和解密密钥的人可能获得钱包控制权。只存小额，并按自己的运营计划定期转出到其他钱包。

面板完整备份需要同时保全数据库和**对应的 `master.key`**；只有数据库中的密文不足以解密热钱包。独立钱包备份作为另一条恢复路径，其文件和口令也要保全。不要把数据库、`master.key` 与备份口令一起上传到公共位置。恢复旧面板快照后仍须核对快照之后的地址高水位，不能据“完整快照恢复成功”推断地址从未被使用。

敏感 API 仅限本站 owner，验证当前管理员密码，拒绝子站代理身份；响应 `no-store`。助记词不进入 URL、浏览器 localStorage/sessionStorage、普通幂等缓存或日志。前端页面能正确运行 WASM、后端能派生地址和备份能解密，分别是钱包管理验证，不是主网收款或资金转出验收。

已实现的自动支付和资金提取见[订单与归集](CRYPTO_TREASURY.md)；完整网络、Token 合约、链最终性、去重与后续链上退款要求见[加密支付设计](CRYPTO_PAYMENTS.md)，当前接口与后续施工划分见[项目文档](projects/crypto-payments/README.md)。
