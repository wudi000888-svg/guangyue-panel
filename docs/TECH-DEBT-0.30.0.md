# 面板框架梳理与技术债（0.30.0）

## 当前框架

面板现在按四个一级区域组织功能，保留原有路由和能力：

| 一级区域 | 功能归类 |
| --- | --- |
| 工作台 | 仪表盘、客户端中心、实时监控 |
| 用户与套餐 | 用户管理、套餐管理、节点组、订阅管理、站内信 |
| 节点与出口 | 本地 IP 池、本地节点、子站节点、公共 IP 池、公共节点、公共订阅、任务中心 |
| 系统与服务 | 账户余额、购买套餐、订单、工单、兑换码、群站管理、配对令牌、运维状态、系统设置 |

“节点组”已经从套餐页面的主要流程中抽出为 `/node-groups`。套餐页仍保留旧的 `?tab=groups` 书签入口，旧链接会继续打开同一组管理视图，但导航和新建入口都指向独立节点组页面。公共代理在系统设置关闭公共功能时由权限过滤隐藏，原路由不删除。

当前版本按已确认的破坏性升级策略执行删除：

- 系统管理员套餐、演示套餐以及默认节点组是安装级资源，禁止删除。
- 普通套餐会直接物理删除，同时清理套餐版本和商品引用；已经发放的用户权益与订单快照不回滚。
- 节点组会直接物理删除，套餐、用户、节点和子站挂载中的旧引用失效；默认系统组仍受保护。
- 前端确认框明确提示影响范围，管理员确认后立即执行。

## 技术债

1. **导航配置仍集中在 `usePanel.ts`**：导航、标题、公共功能过滤和路由跳转规则在一个 composable 中维护。后续应拆成导航模型、权限过滤器和页面上下文三个模块，并用统一的 `NavItem` 类型约束。
2. **套餐页面仍复用节点组编辑组件**：独立路由已经建立，但 `PlansPage.vue` 通过 `mode` 复用组列表和编辑器。后续可以把套餐卡片与节点组卡片拆成页面级组件，减少条件模板和按需加载体积。
3. **删除语义需要资源目录统一**：套餐采用“物理删除或归档”，节点组采用“引用阻断”，节点、IP、业务站仍有各自删除策略。需要统一的删除影响接口和审计事件模型。
4. **套餐引用没有数据库外键**：用户当前权益、套餐队列、商品快照、订单快照都在 JSON 文档中保存。当前由控制面引用扫描保证安全，长期应建立可查询的引用索引，缩短删除检查耗时。
5. **节点来源模型分散**：本地节点、公共节点、挂载子站节点和子站 IP 池分别由不同 API 组合，`source`、`site_id`、`node_id` 需要归并到统一资源目录。
6. **前后端类型手工同步**：Go 的 `Plan`、`NodeGroup` 和 TypeScript 类型分别维护，字段变化容易漏改。应从 OpenAPI 或 JSON Schema 生成公共类型和接口客户端。
7. **权限规则存在三份实现**：前端导航过滤、路由 meta 和后端授权各自判断角色/版本/公共功能。后续应生成权限能力表，前端只负责展示，后端继续作为最终校验点。
8. **套餐切换仍是跨模块状态机**：套餐队列、配额周期、子站同步和撤权由多个循环协作。应抽象统一的 entitlement transition 事件，明确启用、排队、恢复和撤销状态。
9. **国际化目录仍需人工维护**：`check-i18n.mjs` 可以阻止漏翻译，但不能验证语义和上下文。长期应按功能域拆分翻译资源并在 CI 中做语言完整性检查。
10. **完整集成测试耗时较长**：Go 控制面测试和安装矩阵验证仍是发布前的长步骤，应增加快速删除/权限回归测试，并把完整安装测试放到合并后的发布流水线。

## 施工方案

### 已完成（0.30.0）

1. 增加独立节点组路由、侧边栏入口和独立页面标题，保留 `/plans?tab=groups` 兼容入口。
2. 增加 `DELETE /api/plans/:id` 和 `DELETE /api/node-groups/:id`，执行系统资源保护和破坏性物理删除。
3. 在套餐和节点组卡片加入统一确认弹窗、错误反馈和刷新逻辑。
4. 将一级导航收敛为四组，保留全部现有页面和权限逻辑。
5. 补充后端破坏性删除回归测试和本框架技术债文档。

### 下一阶段（0.31.x）

已先落地套餐节点权限选择器：套餐编辑时必须先选节点组，随后只在已选组内展开本站节点；后端同时校验单独节点必须属于所选节点组，避免权限配置和界面展示脱节。

1. 增加 `GET /api/resources/:type/:id/delete-impact`，在确认前展示用户、套餐、节点、订单和挂载影响数量。
2. 建立资源目录表，统一记录资源来源、所属站点、订阅范围、当前状态和可删除策略。
3. 把套餐和节点组卡片拆成独立组件，按路由异步加载，降低首屏代码量。
4. 将导航、路由 meta 和后端能力收敛为共享权限矩阵，补齐 Lite、Pro、主站、子站的矩阵测试。

### 长期

1. 引入可回滚删除和操作审计详情，支持管理员查看删除前后的引用变化。
2. 用 OpenAPI/JSON Schema 生成 Go/TypeScript 类型和 API 客户端。
3. 将套餐权益迁移为显式状态机，并让子站同步、额度结算和撤权都消费同一事件流。
4. 将发布检查拆成 PR 快速校验、合并后安装测试和定期全量回归三层流水线。
