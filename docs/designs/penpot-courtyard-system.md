# 广月面板 · 月庭界面系统（0.33.0）

月庭以中式庭院、月亮和广州塔建立品牌识别，用清晰的任务顺序组织运营功能。登录页保留完整建筑插画，日常工作区把空间留给数据、表单和当前操作。功能按角色呈现，权限、资源类型和既有业务能力继续保留。

## 设计源与本地素材

本轮在本地 Penpot 中创建原生可编辑画板、颜色、Token、组件和原型连接。仓库中的 `docs/designs/penpot/build-penpot.js`、`screens-penpot.js`、`workspaces-penpot.js`、`finish-penpot.js` 记录构建过程，供通过官方 Penpot MCP 复现与维护。`penpot-tokens.json` 是与 CSS 对应的实现参考快照，不是 Penpot 原生文件，也不代表已完成原生导出；导出结果与画面验收单独记录。

- `frontend/public/design/courtyard-night.svg`、`courtyard-day.svg`：原创庭院建筑、广州塔、山水与月色矢量插画。
- `frontend/public/design/moon-seal.svg`：月庭品牌标记。
- `frontend/public/design/noto-serif-brand.ttf`：本地 Noto Serif SC 品牌字子集，来源和许可见同目录 `font-source.txt`、`NotoSerifSC-OFL.txt`。
- `docs/designs/penpot/assets/lucide/`：设计稿使用的 Lucide 图标及许可。页面继续使用项目的 Lucide Vue 组件。

页面字体、插画和品牌标记均从本地资源加载。正文使用系统无衬线字体；`Mooncourt Serif` 仅承担品牌与庭院标题，不增加整套正文网络字体依赖。

## 一个入口、五层样式

`frontend/src/main.ts` 只引入一个全局入口 `frontend/src/styles/index.css`，按下列顺序加载五层基础样式：

| 文件 | 责任 |
| --- | --- |
| `tokens.css` | 语义色、明暗主题、字体、间距、圆角与阴影 |
| `base.css` | 元素基线、排版、焦点、通用工具和减少动态效果 |
| `controls.css` | 按钮、表单、状态、空状态与共享交互控件 |
| `layouts.css` | 整理后的既有业务布局、表格、资源区域和响应式规则 |
| `shell.css` | 登录、侧栏、顶栏、移动导航、功能搜索与远程站点上下文 |

移除七份旧全局样式：`style.css`、`enterprise.css`、`management.css`、`responsive-shell.css`、`console.css`、`penpot-theme.css`、`shell-ui.css`。原业务布局归并到新结构，重复规则与主题覆盖在此轮集中整理。

`styles/member-ui.css`、`styles/admin-ui.css` 与 `commerce.css` 继续负责各自业务页面的局部排版。新增业务规则应使用共享语义变量，局部组件可保留 scoped 样式；不要再创建覆盖全站的主题文件。

共享组件位于 `frontend/src/components/`：

| 组件 | 接口与用途 |
| --- | --- |
| `PageHeading.vue` | `title`、可选 `description` / `eyebrow`；默认内容插槽与 `actions` 插槽，统一页面标题与主操作 |
| `StatusBadge.vue` | `tone` 为 neutral / success / warning / danger / info，可选 `dot`；文字由默认插槽提供 |
| `EmptyState.vue` | `title`、可选 `description`，以及 `icon` / `actions` 插槽；提供空状态原因和下一步 |
| `TablePageLayout.vue` | 组合统一标题、筛选、提示、表格容器与分页，保留完整数据列 |

## 信息架构与完整任务路径

管理员侧栏分为「运营管理」「节点与站点」「服务与支持」「系统管理」；成员侧栏分为「我的服务」「订单与钱包」「帮助与支持」。功能搜索支持中文、英文与 Ctrl/Cmd+K。可见导航和搜索结果复用路由元数据与 `allowedRoute`，继续遵守角色、Lite / Pro 与远程站点权限；UI 分组不替代路由或服务端鉴权。

| 任务 | 页面与反馈路径 |
| --- | --- |
| 登录与进入工作区 | 登录 / 注册 → 角色对应的首页与导航；登录表单提供密码显示控制、提交中与错误反馈 |
| 成员首次连接 | 我的服务 → 开始连接 → 选择设备与客户端 → 核对架构并下载安装 → 复制地址、二维码或下载配置 → 在客户端导入；详细格式与协议仍可展开选择 |
| 购买与开通 | 选购套餐 → 创建待确认订单 → 核对套餐与金额 → 余额确认或已启用的在线支付 → 显示开通状态 → 开始连接；订单状态刷新后同步权益，未完成订单可继续办理 |
| 当前与待恢复套餐 | 我的服务展示当前套餐、流量、重置时间、剩余天数；待恢复套餐展示保留的剩余天数与恢复顺序，成员不用理解节点组和混合订阅术语 |
| 资源到成员授权 | 本地节点 / 子站节点 / 公共节点 → 按来源查看默认节点组 → 套餐中选择整组或组内节点 → 销售配置 → 成员购买与生效权益；套餐模板与当前权益分别可查 |
| 管理子站 | 子站概览 → 定位站点 → 查看状态、预算和挂载资源 → 保存与同步反馈；进入远程管理后持续显示站点上下文，并提供返回本地入口 |
| 退款售后 | 我的订单 → 申请退款 → 显示待审核 → 管理员审核并确认 → 更新退款与权益状态；余额退款与权限撤回仍遵循原业务校验 |
| 工单处理 | 联系支持 / 订单工单 → 提交内容和附件 → 列表与会话即时显示 → 回复、状态与优先级操作；保留会话草稿和历史记录加载 |
| 运营维护 | 用户、监控、钱包、兑换码、消息、任务与系统设置均保留入口；设置按工作区集中组织，避免全部配置平铺 |

商品价格、限购、权益版本、预算结算、资源授权、支付回调和退款规则由原 API 与后端校验。此轮重构界面及其交互状态，不将展示状态当作业务成功。

## 响应式、反馈与无障碍

桌面侧栏宽 224px、顶栏高 68px；900px 及以下切换完整导航抽屉，手机顶栏高 64px。650px 及以下共享标题、操作和详情堆叠为单列。特定业务保留必要的 700 / 760 / 1000px 等布局断点，不把数据列隐藏作为适配方案；表格在容器内滚动或采用既有卡片呈现。

共享按钮桌面高至少 40px、移动端至少 44px；登录按钮高 48px，桌面图标按钮 36px、移动端 44px。移动输入字号 16px。焦点轮廓 2px，常规偏移 3px；深色侧栏采用玉色焦点以保证可见性。

壳层保留跳到内容、搜索焦点约束与恢复、Escape 关闭、抽屉外内容 inert 处理、路由变化后的主内容焦点。列表和主要操作提供加载、禁用、成功、失败、重试及空状态，使用 `role="status"` / `role="alert"` 与 `aria-busy`。新对话框应复用项目焦点管理工具。减少动态效果偏好优先于装饰动画。

桌面钱包仅在桌面挂载，移动端从工具区进入，避免隐藏组件持续轮询。订单与工单继续采用串行轮询和页面卸载清理；刷新不能覆盖较新的请求或吞掉已成功的写入反馈。

## 后续技术债与施工顺序

以下是本轮之后的维护计划，不代表本版本已完成这些架构拆分。

| 债务 | 下一步施工 | 验收重点 |
| --- | --- | --- |
| `usePanel.ts` 仍约一千行，混合会话、资源操作、权益、订阅与轮询 | 按会话、资源、权益 / 订阅、系统 / 任务拆分 composable；暂保留 `panelContext` 对外接口，逐模块替换 | 登录退出、站点切换、CRUD 与订阅刷新无行为回归 |
| 路由、导航名称和展示映射仍分布在多个文件 | 建立同一份路由展示元数据，逐步供标题、侧栏和搜索消费，保留原权限函数 | 管理员 / 成员、Lite / Pro、远程站点的可访问页面矩阵一致 |
| `layouts.css` 保留较多业务选择器 | 按资源、套餐、运营工作区逐步迁移到组件或业务样式文件，先记录使用处再删除旧选择器 | 明暗主题、窄屏和弹窗视觉对照，避免跨页面覆盖 |
| 请求状态在部分页面仍自行管理 | 统一加载、取消、过期响应与写入后刷新的约定，复用 `latestRequest` / `serialPoll`，先覆盖跨站切换与列表编辑 | 断网、慢响应、重复点击与页面离开后无错误状态回写 |
| 跨页面业务闭环需要更稳定的端到端保护 | 增加购买 → 订单 → 开通 → 连接、挂载 → 节点组 → 套餐可见、退款审核、工单回复的隔离环境测试 | 使用真实业务响应断言结果，覆盖失败与重试，不向生产站点写入测试数据 |

每次迁移只收口一个责任边界，结合现有类型检查、单元测试、构建与浏览器验收推进；不得用删除功能降低维护成本。
