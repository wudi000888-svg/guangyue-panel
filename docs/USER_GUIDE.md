# 使用手册

按你的角色开始：成员只需要选择套餐、安装客户端和连接；管理员负责套餐、节点、资源和服务设置。本文描述当前界面。侧边栏中没有的入口，可在 **设置 → 更多功能** 找到。

## 成员：从开通到连接

1. 打开 **购买套餐**，查看价格、额度和有效期。选择套餐后创建订单；免费套餐也需要确认订单。
2. 使用站内余额或管理员启用的付款方式完成付款，在 **我的订单** 查看开通结果。回到付款页面不等于已经到账。
3. 进入 **用户中心／我的订阅**，查看当前套餐、剩余流量、剩余天数和待恢复套餐。
4. 打开 **客户端中心**，按设备系统和 CPU 架构下载客户端。选择面板提供的适合该客户端的订阅格式，导入并更新。
5. 选择可用节点连接。需要帮助时在 **工单中心** 创建工单，可关联自己的订单和有权限使用的节点。

成员不需要设置节点组或选择不同来源的订阅。一个订阅提供当前套餐允许的可用节点；管理员改变当前套餐的节点策略后，服务端更新授权，客户端需更新订阅以刷新缓存。

购买新套餐后，它先开始使用；旧套餐保留剩余时间并暂停。新套餐结束后按页面所示顺序恢复。退款在 **我的订单** 申请，审核前可取消；管理员决定批准或拒绝。金额与权益队列规则见[订单与售后](COMMERCE.md)。

## 管理员：首次配置

1. 按[安装指南](INSTALL.md)完成部署，修改初始管理员密码；在 **系统设置 → 站点与注册** 填写品牌、支持方式和登录提示。
2. 在 **本地节点** 检查默认 VLESS/HY2 直连节点，用真实客户端确认 TCP/UDP 可用。
3. 如需外部出口，在 **本地 IP 池** 添加或导入资源，检测后绑定为新节点；Pro 也可连接子站并挂载其节点。
4. 在 **套餐管理** 设置额度、有效期、协议和可用节点。先选择来源组，再在组内选择整组或部分节点，可设置套餐专属倍率。
5. 在 **用户管理 → 套餐与权益** 手动发放，或在 **套餐上架** 建立销售配置。售价可以为 0，也可限制每位成员购买次数。
6. 确认支付模块状态；外部收款和邮件按需配置。用成员账号完成一次购买、连接、工单和退款流程，再开放注册。

普通成员的节点权限由套餐决定，不提供独立的节点授权配置入口。套餐节点策略即时同步与购买快照的区别见[套餐指南](PLANS.md)。

## 角色、导航和移动端

`owner` 为管理员，管理本站资源与成员；`user` 只能访问自己的套餐、订阅、余额、订单、工单、消息及允许展示的节点目录。成员无法读取其他用户订阅或出口凭证。管理员套餐是预置权益，不代替账号角色。

顶部可切换中文/English、亮暗主题和账户操作。手机通过左上角打开导航抽屉，底部提供常用入口；表格可在内部横向滚动，节点和出口使用卡片及分页。侧边栏可由管理员拖拽调整并自动保存，详见[导航配置](SIDEBAR.md)。

公共 IP 池、公共节点和公共订阅的入口默认隐藏，在系统设置开启 **公共功能显示** 后可见。此偏好属于当前浏览器，只控制显示，不删除数据或停止后台采集。常规/无日志运行模式单独配置，不存在必须切换的简易/专业界面模式。

## 用户和账户

创建成员时分配套餐，按需启停账号。套餐决定协议、有效期、额度和节点范围；手动调整权益前先查看预览。停用、到期或额度用尽会撤回授权，仍启用的到期账号可登录门户处理续费或售后。

- 密码不得留空，最多 72 个 UTF-8 字节；当前允许较短密码，管理员应自行选用足够长的密码。编辑成员时密码留空表示保持原值。
- 修改密码会使原登录会话失效，需要重新登录。
- 重置流量改变统计周期；重置订阅地址轮换订阅凭据；撤销旧配置还会轮换代理凭据。三者影响不同。
- 有资金或工单历史的成员删除后归档，保留业务记录；需先处理未完成订单和余额。
- 当前不提供企业 SSO、多组织隔离或细粒度 RBAC。

开放注册、滑动验证和邮箱验证在系统设置配置；邮箱验证、邮箱绑定及密码找回需先接通 SMTP，参见[邮件指南](EMAIL.md)。

## 节点和出口：先分清路径

| 入口 | 用途 | 客户端连接哪里 |
| --- | --- | --- |
| 本地节点 | 本机接入，使用本机直连或绑定的出口资源 | 本站 |
| 本地 IP 池 | 保存 HTTP/SOCKS5、上游订阅和桥接出口，供本地节点使用 | 通过绑定的本地节点连接本站 |
| 子站节点（Pro） | 挂载子站真实 VLESS/HY2 节点 | 直接连接子站 |
| 子站 IP 池（Pro） | 主站中转，子站 IP 做出口 | 主站 |
| 公共节点 | 公共 IP 池筛选出的代理出口生成的节点 | 本站 |

默认直连节点表示服务器本机出口，不列在私有 IP 池中。绑定出口会创建新节点，不改受保护的默认直连节点。同一出口可有 VLESS/HY2 两种接入，它们的倍率和权限可分别设置。

## 添加与导入出口资源

**添加独立出口**：选择 HTTP 或 SOCKS5，填写服务器、端口及可选凭据，保存后检测。HTTP 指 HTTP CONNECT，不意味着面板与该上游代理之间自动具备 TLS。

文件可导入普通代理清单：

```text
203.0.113.10:8080:demo_user:replace_this_password
203.0.113.11:1080:demo_user:replace_this_password
```

以上为保留网段和示例凭据，不用于真实连接。复杂凭据建议逐项填写或使用正确 URL 编码。完整示例见[代理清单](../examples/proxies.txt)。

**导入订阅或节点**：输入有权使用的 HTTP(S) 订阅地址、分享链接或上传文本。解析器支持常见 Raw/Base64 URI、Mihomo/Clash 配置及部分 Shadowrocket 变体；不是所有客户端私有格式都可导入。VLESS、VMess、Trojan、SS、SOCKS、HTTP、HY2 等上游是否可用取决于解析结果和 Mihomo 支持范围。

导入后核对接受/跳过数量和原因，抽样检测再绑定节点。订阅 URL 常含秘密令牌，不应公开放入 issue、截图或工单；节点名称也不能证明出口位置，以实际检测为准。

**订阅来源**：显示最近更新、下次计划、错误和资源数量，默认约每日错峰更新。删除来源会删除仅由它拥有的出口及绑定节点；被其他来源引用的资源保留。独立出口删除会级联删除绑定节点，影响使用者；客户端需要更新订阅。

## Reality、DNS 和 IPv6

Reality SNI 必须与服务端伪装目标的 TLS 握手兼容。节点默认继承全局 SNI，也可单独指定并验证；不能只改订阅字段而不改服务端。不要用本站域名、内网地址或不兼容的目标。

节点可设置 DNS 和 IPv6 策略。安全模式经配置的 DoH 与对应出口解析；没有 IPv6 能力的上游不会因为开关变成双栈。保护只覆盖进入该节点的流量，客户端仍需正确设置 TUN/代理和 DNS，其他程序可绕过代理联网。

保存后查看应用状态。核心配置或 HY2 路由变化可能使连接短暂重连；“已保存”不代表代理核心或子站已确认应用。

## 订阅、链接和节点广场

成员导入一个套餐订阅，可选 Raw、Base64 或 Mihomo 格式，并按客户端能力筛选协议。管理员可检查不同来源和指定成员。挂载节点带站点来源标记；格式与客户端支持边界见[客户端指南](LIVE-MONITORING.md)。

分享链接与二维码等价于连接凭据，不公开共享。管理员可重置订阅地址；撤销全部旧配置还会轮换代理凭据，并同步收回子站授权。

**节点广场**提供管理员允许展示的线路和适用销售套餐，不提供代理凭据或代替套餐授权。展示开关、节点状态与可用商品共同决定成员目录；没有目录内容时先核对这些条件。

## 质量检测、公共池和监控

质量标签注明来源和采样时间：地理/ASN、代理/VPN/Tor、风险信息和流媒体/AI 页面探测等。缺失显示未知，来源不一致显示冲突。“定位一致”不等于已证明家宽或原生 IP。

测速会消耗服务器和上游流量，延迟不等于持续下载速度，一次通过也不代表长期稳定。公共代理可能失效或记录流量，不适合作为支付和敏感业务的默认出口；先用小规模预算观察资源占用。

管理员 **实时监控** 展示当前站点每位用户的认证连接与上传/下载趋势。连接数不是设备数，空缺数据不按零处理，详见[监控口径](LIVE-MONITORING.md)。

## 常见问题

| 情况 | 先检查 |
| --- | --- |
| 套餐不能购买 | 支付模块、商品上架、限购次数；法币方式还需有效商户配置 |
| 订单已付但未开通 | 后台订单和收款状态、子站结算/同步状态；不要重复付款 |
| 节点为空或缺少节点 | 当前套餐的组内选择、协议、账号/节点启用、到期和额度，子站预算与同步结果 |
| 修改套餐后客户端未变化 | 先确认服务端当前授权，再更新客户端订阅；排队套餐保留快照 |
| 出口与预期不同 | 是否选了绑定出口的新节点，是否仍在用默认直连或旧客户端缓存 |
| 删除后客户端仍有节点 | 更新订阅；旧列表不意味着服务端仍授权 |
| 只显示 IP 不显示国家 | 数据源未提供结果或检测失败，结合检测时间重试 |
| 邮件显示已发送但没收到 | 垃圾邮箱、SMTP 服务商投递记录；发送成功不等于最终送达 |

运行、备份与更新参见[运维说明](OPERATIONS.md)。无日志模式仍保存必要账户、配额、订单和授权数据；上游代理和系统组件也可能各自记录，不是匿名保证。
