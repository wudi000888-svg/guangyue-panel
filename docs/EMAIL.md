# 邮件接入与运维

邮件服务支持注册邮箱验证、成员邮箱绑定、密码找回、订单开通和退款通知。新安装默认关闭，不填写 SMTP 配置也能按站点现有注册策略运行。邮件通过数据库队列异步投递，提交成功表示已入队，不代表邮件已到达收件箱。

## 配置与验收

管理员在系统设置的邮件服务中填写 SMTP 主机、端口、加密方式、账户、SMTP 密码、发件邮箱和发件人名称。保存设置、发送测试邮件、手动重试均需再次输入当前管理员密码；这里的管理员密码与 SMTP 密码是两个不同字段。

| 设置 | 要求 |
| --- | --- |
| SMTP 主机 | 邮件提供商给出的域名或 IP，不包含 `https://`、路径或端口 |
| STARTTLS | 通常使用 587 端口，服务器必须提供并成功完成 STARTTLS |
| TLS | 通常使用 465 端口，从连接建立起即使用 TLS |
| SMTP 账户和密码 | 支持 PLAIN 或 LOGIN 认证；部分提供商需要专用 SMTP 授权码 |
| 发件邮箱 | 必须是提供商允许该账户使用的地址，使用 ASCII 邮箱地址 |
| 面板公开地址 | `PublicURL` 应为成员实际访问的 HTTPS 地址，验证和找回链接由此生成 |

端口可按提供商要求调整。生产和开发模式都要求 SMTP TLS 1.2 或更高版本，并验证证书链和主机名；不存在“忽略证书错误”或明文认证开关。使用私有 CA 时，须通过操作系统的受信任证书存储正确部署根证书，并重启服务使信任配置生效，不要关闭验证。

保存后发一封测试邮件，在投递记录中检查结果，再到收件箱确认。SMTP 接收成功只代表邮件服务器已接收，退信、垃圾邮件分类和最终送达由邮件提供商处理。按提供商指引配置域名验证、SPF、DKIM 和 DMARC，以改善送达率。

读取设置只返回“已保存密码”，不会返回 SMTP 密码。编辑时密码留空表示保留原密码，填写新值才能替换。设置使用版本检查，遇到“邮件设置已更新”时先重新加载，再应用修改，避免覆盖其他管理员的操作。

## 注册、绑定与找回

1. 开放站点注册后，可选择要求注册邮箱验证。必须先完整配置并启用 SMTP，才能开启此要求。
2. 新成员请求验证邮件，在邮件页面点击确认后获得仅用于该邮箱的注册凭证，再完成注册。邮件链接有效期为 20 分钟；确认后注册凭证有效期为 10 分钟，且只能使用一次。
3. 已登录成员可在账户中输入当前密码申请绑定或更换邮箱。确认新邮件前保留原已验证邮箱；确认成功后才切换。一个邮箱只能绑定一个账户。
4. 密码找回仅发送到已验证邮箱。找回页面对不存在、停用和符合条件的账户使用相同响应，不显示账户是否存在。链接有效期为 20 分钟，只能使用一次。
5. 重置密码后，所有旧登录会话和待处理的绑定、找回凭证失效。解绑邮箱也需要当前密码，并使相应凭证失效。

打开邮件链接本身不会消费凭证；必须在面板提交确认，避免邮件安全扫描器提前使用链接。注册时即使邮箱验证不是必填，若提交邮箱，也必须提供该邮箱的有效验证凭证。注册账户、消费凭证和绑定邮箱在同一事务内完成，失败不会留下半完成的注册账户。

邮件发送请求有持久化限流：每个来源 IP、每种用途每 10 分钟最多 20 次，同一收件邮箱跨用途每 10 分钟最多 5 次。验证与账户密码检查另有接口限流。频繁点击不会提高送达速度，等待并检查垃圾邮件即可。

## 订单通知

启用订单通知后，系统发送此后发生的套餐开通和退款完成事件，不批量补发旧事件。成员必须在事件发生时已绑定验证邮箱；邮件不会替代原有站内通知。

事件入队与事件回执在同一事务内完成，同一个事件只建立一条邮件队列记录。投递前会再次核对成员当前绑定邮箱和账户状态；邮箱已变更、解绑或账户不可用时，订单邮件取消投递，避免把账户信息继续发到旧邮箱。

## 投递状态与重试

| 状态 | 含义及处理 |
| --- | --- |
| `pending` | 已入队，等待后台发送 |
| `sending` | 已被工作进程领取，正在发送 |
| `retry` | 发送失败，等待退避时间后重试 |
| `sent` | SMTP 已接受邮件，不等同于最终送达收件箱 |
| `failed` | 自动尝试已用尽；修复设置后可由管理员手动重试 |
| `expired` | 验证邮件已过期；成员需重新申请链接 |
| `cancelled` | 收件邮箱已变化或账户不可用，订单通知已取消 |

后台约每 5 秒检查队列，每轮最多处理 5 封；SMTP 每次连接有超时，总处理时限为 40 秒。队列使用 120 秒领取租约，进程意外退出后能够恢复。自动发送最多尝试 5 次，失败间隔从 30 秒开始按指数增长。

管理员可重试未过期的 `failed` 或 `retry` 邮件，重置本轮尝试次数；已发送、已过期、已取消和正在发送的邮件不能直接重试。关闭 SMTP 会暂停发送。投递记录保留脱敏的失败阶段，不展示 SMTP 密码、验证链接或邮件正文。

SMTP 采用 **at-least-once（至少一次）投递模型，并设置有限重试次数**，不是保证一定送达。邮件服务器接受 DATA 后，如果确认响应在网络中丢失，重试可能产生重复邮件。重试使用固定 Message-ID，但是否去重取决于收件服务器。正常收到 DATA 成功响应后，QUIT 失败不会触发重发。

当前没有自动清理邮件投递历史的保留策略，管理员应监控数据库与备份大小。过期凭证在过期超过一天后清理，发送限流记录保留约一天。不要直接删除尚在发送的队列记录或凭证来处理故障。

## 备份与排错

SMTP 设置和邮件正文使用站点 `master.key` 加密，验证凭证表仅保存令牌哈希。邮件正文包含真实操作链接，因此完整备份和数据库仍属于敏感数据；拥有数据库及对应主密钥即可解密这些内容。

使用面板完整备份，同时保留数据库与匹配的 `master.key`。恢复或 Lite → Pro 迁移必须沿用配套密钥，不能只复制数据库或用新密钥覆盖旧密钥。邮件配置、绑定关系、队列和事件回执均包含在完整备份中。恢复会恢复当时的队列状态：备份之后已投递的消息可能被再次投递，验证邮件仍受原有效期限制。

常见失败处理：

- **连接失败**：检查 SMTP 主机、端口、DNS、云服务器出站限制和服务商连接要求。
- **TLS 验证失败**：检查加密模式、证书主机名、有效期、证书链与系统时间。使用邮件服务商提供的正确主机名，不绕过验证。
- **认证失败**：检查 SMTP 是否启用、账户及授权码是否匹配、提供商是否限制发件来源。
- **发件人或收件人失败**：检查地址及服务商授权、域名验证和发送限额。
- **`sent` 但未收到**：检查垃圾箱和邮件服务商投递日志；面板目前不自动接收退信或邮件打开回执。
- **链接跳转错误**：核对 `PublicURL`、HTTPS 证书和反向代理地址；修改后重新申请邮件，不复用旧链接。

自动化测试使用本机临时 SMTP 服务和测试专用根证书，覆盖 TLS、STARTTLS、认证失败、证书验证、队列恢复、一次性凭证和权限控制，不向真实邮箱发信。
