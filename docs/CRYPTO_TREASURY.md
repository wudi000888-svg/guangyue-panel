# 订单收款与资产归集

本文件记录 v0.40.0 订单自动分配地址、余额查询与管理员发起归集的业务规则。自动收款与提取开放 Ethereum、BNB Smart Chain、Plasma 和 Solana；Arbitrum、OP 和 Base 仅保留 API 配置与余额读取（须钱包显式支持该链及有效 RPC），当前界面不提供入口，因缺少 L1 最终性适配不开放自动资金操作。实际接口以实现和接口文档为准。创建并备份钱包后选链、选币并一键启用，面板自动取得双独立公共 RPC 与人民币行情并执行预检；无需手填 URL 或汇率。公共服务不可用时明确失败并保留原配置，不降低最终性检查。

## 用户付款

支付模块有单独的总开关。独立站默认开启；业务子站及首次被管理令牌接管的站点默认关闭。子站管理员可以在“系统设置 → 交易与接入 → 在线支付”验证密码后重新开启，后续主站轮询不会覆盖该决定。只读令牌不改变支付状态。关闭时禁止新订单、在线付款、兑换码充值和新提取授权，保留历史查询、真实到账核对及已批准任务的执行；邮件服务独立配置。

用户建立普通套餐订单后，选择加密货币、网络与资产时，服务端自动生成专属收款地址。管理员不需要逐单生成地址，也不需要保持浏览器在线。免费订单、余额支付和法币渠道不会消耗新的钱包地址。

地址、钱包身份、派生索引、订单、网络、Token 合约和冻结应付数量在数据库事务中关联。重复提交同一付款请求返回原付款单。同一资产不生成第二张付款单，切换资产或网络才消耗新地址；每张订单最多 12 张历史付款单。付款取消、过期、完成或切换网络均不回收地址；历史地址继续保存并检查后续转入。新建付款单不能重新分配旧地址。

订单报价仍来自人民币套餐价格。链上数量使用任意精度整数，接口用十进制字符串；USDT、USDC、USDT0 的不同链及合约或 mint 分别处理，不按简称猜测资产。一键启用使用 CoinGecko/Coinbase 公开行情，后台提前刷新有效期；两个有效来源偏差超过 2% 或稳定币 USD 价格超出 0.95–1.05 时停止新报价。临时失联保留仍有效的报价，到期拒绝新付款单；既有付款单按原快照继续核对。高级手动汇率明确标为手动。

系统区分待付款、少付、待确认、已收款、开通中、已开通与需要处理。少付可以在同一地址补足。最终确认的真实 Transfer 才参与收款累计；Gas、未知币、错链付款或失败交易不会开通套餐。订单取消、晚付、超付或已有其他渠道付款时仍保存资金事实，不静默丢弃实际收入。

同一链事件以网络标识、交易身份和事件位置建立唯一身份：EVM 为交易哈希与日志序号，Solana 为区分大小写的交易签名与稳定的收款人净增事件位置；重复扫描、RPC 重试和进程重启不能重复认款。所有渠道竞争同一订单付款归属；同一订单只开通一次。

## 余额视图

管理员默认查看全部钱包资产卡片，桌面使用瀑布布局，手机单列。按网络和资产查询历史地址，可筛选有余额的地址，并查看关联订单、余额及查询时间。不同网络的 ETH、BNB 和 Token 分开显示，不直接相加。资产总览默认每 15 秒刷新，地址详情每 30 秒刷新，可暂停；隐藏页面或切换钱包/网络时取消旧请求，已加载分页逐页刷新并统一更新。返回的余额是明确区块上的链上快照，查询失败保留最后成功记录并显示状态，不能把失败显示成零余额。

Gas 参考价使用独立轻量接口，每 5 秒查询，后台缓存不超过 4 秒，不随资产列表刷新重新扫描全部收款地址。显示价格、资金余额、区块、最后查询时间及失效状态。链出块和最终性进度不受前端查询频率控制。费用旁显示约合 USD 和人民币；按 ETH、BNB、SOL、XPL 的真实市场单价精确换算，Solana 使用 9 位 lamports、EVM 使用 18 位原子单位。行情由独立、每进程单飞的 CoinGecko 公开接口约每分钟刷新，5 分钟后过期，不延迟 Gas RPC。来源、原始行情时间与异常单独展示。行情只是费用说明，绝不作为订单兑换价、签名意图、费用上限或到账确认依据。Solana 实际转账手续费由序列化消息的 getFeeForMessage 核验，不能按 EVM 的 Gwei 换算。

查询涉及历史地址，包括已取消、过期或已归集的付款单。曾归集过的地址再次收到款后仍需出现在余额视图。地址永不删除或重新分配。

## 固定 Gas 资金地址

每个可签名的内置热钱包创建后立即显示单独用途的固定资金地址；无需 RPC 可复制并提前充值。只提供该钱包支持网络的操作选项。该地址与订单接收分支分开，不会被分配给订单。管理员向它转入所选网络的原生手续费币：Ethereum、Arbitrum、OP 和 Base 使用所在网络的 ETH，BNB Smart Chain 使用 BNB，Plasma 使用 XPL。Solana 使用独立的 ed25519 派生资金地址并只充值 SOL。同一个地址字符串在不同链上有独立余额；不会自动跨链或兑换。

EVM 固定地址的余额支付两类费用：向订单地址补足的原生币，以及补款交易自身的手续费。Token 转账的手续费从各订单地址支出。外部 xpub 不能签名，保留自动派生和余额查询能力，资金转出仍由外部钱包处理；不能因为面板拥有公钥就显示后台可提现。Solana 的固定 SOL 地址直接作为归集交易 fee payer，与收款地址共同签名，无需逐地址补充 SOL；新收款目标 ATA 的租金单独显示并与交易费相加，形成本次总成本及批准上限。普通 Plasma 归集使用 XPL，不把支付产品的 Gas 代付或未来功能假设为所有交易免费。

## 管理员发起提取

只有管理员确认归集后，后台才会支付手续费；用户到账、余额刷新、Gas 查询和只读预估不会补款。EVM 自动补 Gas 仅限同钱包、同网络的真实订单地址，所选白名单稳定币当前余额必须严格大于 0.1，等于 0.1 也不补；执行前再次核对当前余额未被转走且足以覆盖已批准提取数量。Solana 固定资金地址代付遵守相同门槛。手动地址不自动补 Gas，可自行准备手续费后提取；原生币回收保留独立逻辑。

提取以一次明确的管理员操作为起点。管理员选择网络、币种、每个地址的最低 Token 余额和收款地址，系统先查询并生成预览：符合条件的地址、预计可转出的数量、原生币补款差额、补款与 Token 转账的预计手续费、Gas 资金余额及费用上限。默认无需填写费用上限，由有限缓冲的本次估算自动设置并随报价冻结；高级接口允许明确更低或更高的有限预算。

收款地址必须在对应网络有效（EVM 十六进制地址，Solana 严格的 32 字节 base58 公钥），不能使用 Token 合约、Gas 资金地址或本次来源地址作为归集目标。界面始终显示网络和 Token 合约，选择币种不会进行兑换，也不会把不支持的资产一起转走。

转账输入有效时，页面每 5 秒串行请求只读费用预览；地址较多时等待本次完成，独立 Gas 参考查询继续运行。隐藏或退出后取消查询。预览不会广播、补 Gas 或创建提取任务。

点击核对后固定钱包、网络、币种、收款目标和服务端密封报价；后台刷新不会替换正在确认的交易。有效性或费用未知时禁止确认，过期后需重新预估。管理员确认并验证当前密码后创建持久任务。收款目标、网络、资产、来源地址、计划数量与预算随任务冻结；之后在界面更改输入不改变已批准任务。

每个 EVM 来源地址按以下顺序执行：

1. 重新核对 Token 和原生币余额，计算 Token 转账需要的手续费。
2. 如果已有原生币够用，不补款；不足时只补差额。
3. 固定资金地址签署补款交易，先持久保存交易和 nonce 再广播。
4. 补款达到可使用的链上确认条件后，再核对实际余额和 Token 转账估算。
5. 签署并持久保存 Token 归集交易，再广播。
6. 收到成功的规范链 receipt 且核对转出资产、来源、目标、数量后，更新任务状态；只有达到对应确认条件才显示完成。

预估费用随网络改变，不能保证“刚好”覆盖最终实际费用。应按当前估算和有限缓冲计算缺口，并受管理员批准的费用上限约束；实际 gasUsed 通常低于 gasLimit，少量原生币可能留在来源地址。Gas 单价、实际用量或 Solana 手续费/租金超过已批准上限时进入 `fee_review_required`，停止新补款和新转账，费用回落也不自动恢复。管理员用当前密码核对并重试仍受原预算约束；提高预算须安全结束未执行步骤，再重新预估和确认。已签交易继续核对原交易，不能重新补款。资金不足、Token 暂停或余额变化给出明确原因，不能无限补款或偷偷突破预算。

EVM 使用双来源较高的真实 gasPrice，并按本次交易 estimateGas 加 10% 用量缓冲。费用卡片提供经济（原始单价）、标准（单价加 10%）、优先（单价加 20%）和自定义（当前单价至其 1.25 倍）选项；标准档双重缓冲约 21%，补款只覆盖一次归集的批准手续费减去已有原生币余额。费用包含必要的补款交易费，显示原生币与约 USD/CNY，不编造固定确认秒数。自定义是现有 EIP-155 交易的单价上限，不冒充尚未实现的 EIP-1559 priority fee 配置。Token 估算要求 RPC 支持零费率模拟或 state override，后者仅临时模拟原生币余额；不改合约和 Token 存储，不支持的服务会明确暂停。L2 还需数据发布与 L1 最终性适配，当前关闭自动资金操作。

Solana 自动扫描支持 legacy / v0 / v1 交易；未知 v2 及后续交易版本明确报需人工核对，不降低凭据校验。实际收款按所有同一收款人/mint 账户的真实前后净增核对，失败 CPI、内部调拨或缺失元数据不能开通套餐。自动认单只接受 canonical ATA，外部 delegate / close authority 或复杂款项保留待核对。

Solana 归集另行构建受限的 legacy 交易消息：核对官方 SPL Token Program、mint、来源所有权、目标 ATA、金额、真实消息手续费与租金；只在已批准租金时允许创建目标 ATA。签名并持久保存完整原始交易及两位签名者意图后再广播。最终执行必须同时具备规范链交易、明确成功的 meta.err、真实手续费与资金地址前后余额证明，缺失字段不能标为完成。既有区块哈希过期或广播结果不明时只追踪原签名，不能自动换哈希重签一笔新交易。

## 幂等、恢复与查询

同一钱包在同一链只允许一个活跃提取任务。预览有效期为 120 秒，并绑定管理员、钱包、网络、目标、来源、数量和费用；同一报价只生成一个任务，即使换请求键也返回原任务。EVM Gas 资金地址在同一链上的 nonce 统一预留；多个任务不能签出冲突 nonce。Solana 不使用 EVM nonce，完整签名、消息及区块哈希是不可变的交易身份。管理员连续点击、网页刷新或重试同一请求返回同一任务。

广播前保存签名交易、预期哈希、链、来源、nonce、目标、金额及费用。网络超时不是交易未发送的证明。恢复后查询原哈希，必要时重新广播原交易；不能用新 nonce 重做一笔不知道是否成功的补款或归集。

交易失败与交易尚未确认分别展示。已发生的链上费用不会因为取消任务而退回。仅在所有已签署交易均完成最终核验时允许结束任务；存在未知或待确认交易时拒绝取消，并继续检查原交易。结束任务阻止尚未签署的后续操作。最终确认后的提取记录长期保留。

钱包可移植备份与面板完整数据库备份职责不同。迁移运行中的收款和资金任务时必须保留数据库、对应 master.key、订单地址映射、扫描进度、签名交易和 nonce 高水位；不能只导入钱包助记词就假定历史订单和资金任务可恢复。

## 热钱包提示

面板服务器托管内置热钱包，运行中的服务器具有签名能力。界面保持“小额存放、定期转走”的明确提醒。外部 xpub 方案仅保存公钥，不获得资金控制权。自动补 Gas 和归集不改变这两种方案的私钥边界。

本轮工程验证使用隔离 RPC 和无价值环境，不向用户真实钱包广播交易。代码和安装包的验收不代表任意 RPC 供应商或所有主网资产已完成运营验收；内置公共 RPC 在启用时执行完整只读预检，实际可用性与限流仍取决于服务商；不能把公共只读探测视为主网资金验收。
