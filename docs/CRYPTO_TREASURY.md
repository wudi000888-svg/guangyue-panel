# 订单收款与资产归集

本文件记录 v0.38.0 订单自动分配地址、余额查询与管理员发起归集的业务规则。自动收款、Gas 补款和提取目前仅开放 Ethereum 与 BNB Smart Chain；Arbitrum、OP 和 Base 仅保留 API 配置与余额读取（须钱包显式支持该链及有效 RPC），当前界面不提供入口，因缺少 L1 最终性适配不开放自动资金操作。实际接口以实现和接口文档为准。创建并备份钱包后选链、选币并一键启用，面板自动取得双独立公共 RPC 与人民币行情并执行预检；无需手填 URL 或汇率。公共服务不可用时明确失败并保留原配置，不降低最终性检查。

## 用户付款

支付模块有单独的总开关。独立站默认开启；业务子站及首次被管理令牌接管的站点默认关闭。子站管理员可以在“系统设置 → 交易与接入 → 在线支付”验证密码后重新开启，后续主站轮询不会覆盖该决定。只读令牌不改变支付状态。关闭时禁止新订单、在线付款、兑换码充值和新提取授权，保留历史查询、真实到账核对及已批准任务的执行；邮件服务独立配置。

用户建立普通套餐订单后，选择加密货币、网络与资产时，服务端自动生成专属收款地址。管理员不需要逐单生成地址，也不需要保持浏览器在线。免费订单、余额支付和法币渠道不会消耗新的钱包地址。

地址、钱包身份、派生索引、订单、网络、Token 合约和冻结应付数量在数据库事务中关联。重复提交同一付款请求返回原付款单。同一资产不生成第二张付款单，切换资产或网络才消耗新地址；每张订单最多 12 张历史付款单。付款取消、过期、完成或切换网络均不回收地址；历史地址继续保存并检查后续转入。新建付款单不能重新分配旧地址。

订单报价仍来自人民币套餐价格。链上数量使用任意精度整数，接口用十进制字符串；USDT、USDC 的不同链及合约分别处理，不按简称猜测资产。一键启用使用 CoinGecko/Coinbase 公开行情，后台提前刷新有效期；两个有效来源偏差超过 2% 或稳定币 USD 价格超出 0.95–1.05 时停止新报价。临时失联保留仍有效的报价，到期拒绝新付款单；既有付款单按原快照继续核对。高级手动汇率明确标为手动。

系统区分待付款、少付、待确认、已收款、开通中、已开通与需要处理。少付可以在同一地址补足。最终确认的真实 Transfer 才参与收款累计；Gas、未知币、错链付款或失败交易不会开通套餐。订单取消、晚付、超付或已有其他渠道付款时仍保存资金事实，不静默丢弃实际收入。

同一链事件以 Chain ID、交易哈希和日志序号建立唯一身份；重复扫描、RPC 重试和进程重启不能重复认款。所有渠道竞争同一订单付款归属；同一订单只开通一次。

## 余额视图

管理员按网络和资产查询历史地址，可筛选有余额的地址，并查看关联订单、余额及查询时间。不同网络的 ETH、BNB 和 Token 分开显示，不直接相加。余额页面默认每 25 秒刷新，可暂停；隐藏页面或切换钱包/网络时取消旧请求，已加载分页逐页刷新并统一更新。返回的余额是明确区块上的链上快照，查询失败保留最后成功记录并显示状态，不能把失败显示成零余额。

查询涉及历史地址，包括已取消、过期或已归集的付款单。曾归集过的地址再次收到款后仍需出现在余额视图。地址永不删除或重新分配。

## 固定 Gas 资金地址

每个可签名的内置热钱包创建后立即显示单独用途的固定资金地址；无需 RPC 可复制并提前充值。只提供该钱包支持网络的操作选项。该地址与订单接收分支分开，不会被分配给订单。管理员向它转入所选网络的原生手续费币：Ethereum、Arbitrum、OP 和 Base 使用所在网络的 ETH，BNB Smart Chain 使用 BNB。同一个地址字符串在不同链上有独立余额；不会自动跨链或兑换。

固定地址的余额支付两类费用：向订单地址补足的原生币，以及补款交易自身的手续费。Token 转账的手续费从各订单地址支出。外部 xpub 不能签名，保留自动派生和余额查询能力，资金转出仍由外部钱包处理；不能因为面板拥有公钥就显示后台可提现。

## 管理员发起提取

提取以一次明确的管理员操作为起点。管理员选择网络、币种、每个地址的最低 Token 余额和收款地址，系统先查询并生成预览：符合条件的地址、预计可转出的数量、原生币补款差额、补款与 Token 转账的预计手续费、Gas 资金余额及费用上限。默认无需填写费用上限，由有限缓冲的本次估算自动设置并随报价冻结；高级接口允许明确更低或更高的有限预算。

收款地址必须在对应 EVM 网络有效，不能使用 Token 合约、Gas 资金地址或本次来源地址作为归集目标。界面始终显示网络和 Token 合约，选择币种不会进行兑换，也不会把不支持的资产一起转走。

管理员确认并验证当前密码后创建持久任务。收款目标、网络、资产、来源地址、计划数量与预算随任务冻结；之后在界面更改输入不改变已批准任务。

每个来源地址按以下顺序执行：

1. 重新核对 Token 和原生币余额，计算 Token 转账需要的手续费。
2. 如果已有原生币够用，不补款；不足时只补差额。
3. 固定资金地址签署补款交易，先持久保存交易和 nonce 再广播。
4. 补款达到可使用的链上确认条件后，再核对实际余额和 Token 转账估算。
5. 签署并持久保存 Token 归集交易，再广播。
6. 收到成功的规范链 receipt 且核对转出资产、来源、目标、数量后，更新任务状态；只有达到对应确认条件才显示完成。

预估费用随网络改变，不能保证“刚好”覆盖最终实际费用。应按当前估算和有限缓冲计算缺口，并受管理员批准的费用上限约束；实际 gasUsed 通常低于 gasLimit，少量原生币可能留在来源地址。费用上涨、资金不足、Token 暂停或余额变化时等待或给出明确失败原因，不能无限补款或偷偷突破预算。

本轮使用两来源较高的 gasPrice 与 estimateGas，并各加 20% 有限缓冲，签署 EIP-155 交易。Token 估算要求 RPC 支持零费率模拟或 state override，后者仅临时模拟原生币余额；不改合约和 Token 存储，不支持的服务会明确暂停。L2 还需数据发布与 L1 最终性适配，当前关闭自动资金操作。

## 幂等、恢复与查询

同一钱包在同一链只允许一个活跃提取任务。预览有效期为 120 秒，并绑定管理员、钱包、网络、目标、来源、数量和费用；同一报价只生成一个任务，即使换请求键也返回原任务。Gas 资金地址在同一链上的 nonce 统一预留；多个任务不能签出冲突 nonce。管理员连续点击、网页刷新或重试同一请求返回同一任务。

广播前保存签名交易、预期哈希、链、来源、nonce、目标、金额及费用。网络超时不是交易未发送的证明。恢复后查询原哈希，必要时重新广播原交易；不能用新 nonce 重做一笔不知道是否成功的补款或归集。

交易失败与交易尚未确认分别展示。已发生的链上费用不会因为取消任务而退回。仅在所有已签署交易均完成最终核验时允许结束任务；存在未知或待确认交易时拒绝取消，并继续检查原交易。结束任务阻止尚未签署的后续操作。最终确认后的提取记录长期保留。

钱包可移植备份与面板完整数据库备份职责不同。迁移运行中的收款和资金任务时必须保留数据库、对应 master.key、订单地址映射、扫描进度、签名交易和 nonce 高水位；不能只导入钱包助记词就假定历史订单和资金任务可恢复。

## 热钱包提示

面板服务器托管内置热钱包，运行中的服务器具有签名能力。界面保持“小额存放、定期转走”的明确提醒。外部 xpub 方案仅保存公钥，不获得资金控制权。自动补 Gas 和归集不改变这两种方案的私钥边界。

本轮工程验证使用隔离 RPC 和无价值环境，不向用户真实钱包广播交易。代码和安装包的验收不代表任意 RPC 供应商或所有主网资产已完成运营验收；内置公共 RPC 在启用时执行完整只读预检，实际可用性与限流仍取决于服务商；不能把公共只读探测视为主网资金验收。
