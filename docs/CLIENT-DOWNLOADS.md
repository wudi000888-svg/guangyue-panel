# 让成员从本站下载客户端

客户端下载中继适合成员难以直连 GitHub 安装包的场景。管理员在 **系统设置 → 下载与访问** 开启 **客户端下载中继**，成员登录后即可从客户端中心下载受支持的固定安装包。**默认关闭**。

本站服务器仍需能访问 GitHub，中继的速度取决于服务器网络、缓存和并发负载，不承诺固定加速效果。App Store、F-Droid 和官方发布页继续直接打开原站。

## 成员如何使用

1. 在客户端中心选择操作系统和架构，核对安装包类型。
2. 点击下载；支持中继的 GitHub Release 安装包使用本站路径，其他入口打开官方来源。
3. 下载失败可重试或改用官方下载。安装后按[客户端指南](LIVE-MONITORING.md)选择订阅格式。

中继不是任意 URL 下载代理，只接受项目目录中已登记的 HTTPS GitHub `releases/download` 安装包。它不转发成员 Cookie、授权头或来源页面给 GitHub。

## 缓存与限制

同一资源的并发读取共享上游下载，完整缓存最长保留 24 小时；超过磁盘上限清理未使用旧文件。缓存不进入业务状态目录或升级备份，关闭中继拒绝新请求，正在进行的下载可完成。

| 限制 | 值 |
| --- | --- |
| 同时上游下载 | 最多 2 个 |
| 下载请求 | 最多 8 个 |
| 单安装包 | 512 MiB |
| 缓存＋进行中下载 | 最多 1 GiB |
| 上游总耗时 | 最多 10 分钟 |
| 客户端响应 | 最多 20 分钟 |

最后一位读取者取消后，未完成下载停止并删除残留。上游失败或超过限制时不会把部分文件报告成成功安装包。完整缓存支持 Range / If-Range；未完成资源收到 Range 时返回完整 `200` 和 `Accept-Ranges: none`，客户端应从头下载，不能追加到原部分文件。HEAD 不主动填充空缓存。

## 目录维护与来源校验

前端 `frontend/src/data/clients.json` 是唯一手工目录，后端按客户端 ID 和完整下载数组索引查找，不按平台筛选后的序号定位文件，避免架构错配。修改后运行：

```bash
python3 scripts/sync-client-catalog.py
python3 scripts/check-client-links.py
```

构建同步目录，测试和发布检查拒绝快照漂移。接口 `GET /api/clients/download/{clientID}/{downloadIndex}` 要求登录 Cookie；上游重定向限定 GitHub 及登记资产域名，每次连接解析并拒绝非公网目标，不使用环境代理。

缓存 SHA256 用于内容标记，不等同发行者签名。安装包来源依赖官方目录地址和 TLS；目录更新仍需核对版本、架构、来源和许可。
