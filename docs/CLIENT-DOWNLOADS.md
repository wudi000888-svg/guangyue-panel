# 客户端安装包站点中继

管理员开启「客户端下载中继」后，已登录成员和管理员可从面板下载目录中固定版本的 GitHub Release 安装包。默认关闭。App Store、F-Droid 和官方发布页继续直接打开原站；服务器不会代理任意输入的 URL。

前端目录 `frontend/src/data/clients.json` 是唯一手工维护来源。后端按客户端 ID 和完整下载数组索引查询，避免按平台筛选后错配 ARM64、Intel 或 Windows 安装包。修改目录后运行 `python3 scripts/sync-client-catalog.py` 更新 Go 嵌入快照；构建会同步，测试和发布检查会拒绝目录漂移。

`GET /api/clients/download/{clientID}/{downloadIndex}` 使用现有登录 Cookie。服务端仅接受目录中的 HTTPS GitHub `releases/download` 静态安装包，重定向只允许 GitHub 与其固定资产域名；每次建立连接前解析并拒绝任何非公网地址，直接连接检查后的 IP。不使用环境代理，不向上游发送成员 Cookie、授权头或来源页面。

安装包边下载边写入临时文件并下发，同一资源的并发请求共享一个上游下载。完整缓存保留至多 24 小时，下次访问时清理过期项；磁盘空间达到上限时淘汰未使用的旧文件。进程正常退出时清理缓存，标准 systemd 部署也会在服务停止后清理私有临时目录。缓存不进入面板状态目录或升级备份。

固定资源限制：最多 2 个同时进行的上游下载、8 个下载请求、单包 512 MiB、缓存及进行中下载合计最多 1 GiB；上游总耗时最多 10 分钟，客户端响应最多 20 分钟。最后一个读取者取消时停止未完成下载并删除残留。超过限制或上游故障时显示失败，可使用官方下载；已开始的异常传输会断开，避免把不完整安装包报告为成功。

完整缓存支持标准 HTTP Range / If-Range，缓存校验标记使用实际内容 SHA256。未缓存或仍在下载的资源收到 Range 时返回完整 `200` 响应及 `Accept-Ranges: none`；客户端需要从头下载，不能将其追加到旧部分文件。HEAD 不会主动下载尚未缓存的安装包。关闭中继后拒绝新的下载请求，已开始的下载可继续完成。

安装包信任来自目录中的官方发布地址与 TLS 校验；这里的缓存 SHA256 用于 HTTP 内容标记，不等同于发行者签名验证。目录版本与链接更新需随面板发布评审。
