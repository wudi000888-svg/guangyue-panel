# Guangyue Panel · 广月面板

**Один домен. Тарифы, узлы и сайты в одной панели.**

Панель для самостоятельного размещения прокси-сервисов и управления сетевыми ресурсами. Запускайте VLESS Reality/Vision и Hysteria 2, управляйте выходными IP и независимыми сайтами, выдавайте подписки на основе тарифов. Серверная часть написана на Go, интерфейс — на Vue 3. Lite подходит для отдельного сайта, Pro — для централизованного управления несколькими сайтами.

## Начало работы

Подготовьте сервер и домен. Мастер установки проверит окружение и настроит приложение, прокси-ядра, сертификаты и необходимую базу данных. **По умолчанию используется Docker; можно выбрать нативную установку с systemd.** Панель и стандартные узлы могут работать на одном домене.

- Направьте домен непосредственно на сервер и **отключите проксирование CDN**. В Cloudflare выберите **DNS only**, без оранжевого облака.
- Публичные порты **TCP 443 и UDP 443** должны быть свободны и разрешены в межсетевом экране и облачной группе безопасности. Установщик не выбирает другой порт и не перехватывает существующие HTTPS-сервисы.
- Нужен полноценный сервер Linux amd64/x86_64 с root или sudo. Предварительная проверка принимает Debian 12/13 и Ubuntu 22.04/24.04; нативная установка на виртуальных машинах проверяется на Ubuntu 22.04/24.04. Это не означает проверку всех возможных конфигураций этих систем.
- Docker пока публикует только IPv4: используйте записи A без AAAA. Для IPv6 выберите нативный режим. Начальная рекомендация — 1 CPU / 1 GiB для Lite или 2 CPU / 2 GiB для Pro; оставьте запас места для данных и резервных копий.

Скопируйте весь блок в терминал сервера:

```bash
gy_install_file=$(mktemp)
curl --proto '=https' --proto-redir '=https' -fsSL \
  https://github.com/wudi000888-svg/guangyue-panel/releases/latest/download/install.sh \
  -o "$gy_install_file" && sudo bash "$gy_install_file"
rm -f "$gy_install_file"
```

До подтверждения плана мастер проверяет DNS, порты, ресурсы и конфигурации Nginx/Docker. Сертификаты выпускаются и продлеваются через TLS-ALPN-01 на TCP 443; существующий Nginx на HTTP 80 сохраняется. Компоненты и образы берутся из выбранного выпуска и проверяются по контрольным суммам.

После установки откройте указанный приватный файл первоначального аккаунта, смените пароль и проверьте VLESS и HY2 настоящим клиентом. Настройте регистрацию, публикацию тарифов и почту. На независимом сайте платёжный модуль включён по умолчанию, но внешним каналам нужны действующие реквизиты и настройка. При первом подключении дочернего сайта под управление главного его платежи по умолчанию отключаются. Купить тариф можно только после публикации его предложения.

Для уже работающего сайта используйте [обновление и откат](docs/UPDATES.md), а не переустановку поверх данных. В [руководстве по установке](docs/INSTALL.md) описаны проверка `--check`, продолжение `--resume` и ограничения развёртывания.

## Lite или Pro

| | Lite | Pro |
| --- | --- | --- |
| Основное назначение | Независимый сайт | Главный сайт для управления другими |
| Постоянные данные | SQLite | PostgreSQL |
| Кеш и задания | Ограниченный локальный кеш и постоянная очередь | Redis и постоянная очередь |
| Подключение к главному сайту | Создать токен дочернего сайта | Создать токен при работе дочерним сайтом |
| Управление дочерними сайтами | Недоступно | Подключение импортом их токена |
| Развёртывание | Docker или systemd | Docker или systemd |

**Дочерний сайт создаёт токен, Pro импортирует его.** Регистрационный файл не нужен. Токен может иметь срок действия или действовать до отзыва. Сайт сохраняет своих администраторов, аккаунты, данные и локальные сервисы; местный администратор может отозвать доступ. Подробнее: [редакции](docs/EDITIONS.md) и [управление сайтами](docs/BUSINESS-SITES.md).

## Возможности

- **Узлы и выходные IP:** локальные VLESS Reality/Vision и HY2, выходы HTTP CONNECT/SOCKS5, импорт подписок, на использование которых есть разрешение. Общедоступные источники и сбор ресурсов необязательны.
- **Дочерние сайты:** права управления, подключение узлов, общие бюджеты и периоды восстановления, выборочные показатели трафика и соединений, проверка и запуск поддерживаемых обновлений из Pro.
- **Тарифы и подписки:** целые группы источников или отдельные узлы внутри группы, квота, срок и коэффициенты расхода для конкретного тарифа. Новый тариф приостанавливает оставшийся срок предыдущего; прежние права возобновляются по очереди.
- **Продажи и поддержка:** заказы, баланс, коды активации, возвраты с одобрением администратора, обращения, SMTP, EPay V1 и Stripe Checkout. Внешние сервисы нужно настроить и проверить отдельно.
- **Криптоплатежи:** постоянный адрес заказа при выборе этого способа оплаты, балансы, адреса с поступлениями, оценка Gas и подтверждаемая консолидация средств. Автоматическое подтверждение и консолидация поддерживаются для доступных активов USDT/USDC в Ethereum, BNB Smart Chain, Plasma и Solana. Возможность настроить L2 не означает поддержку этих автоматических операций.
- **Повседневная работа:** китайский и английский интерфейс, светлая и тёмная темы, мобильная вёрстка, настраиваемое меню, уведомления, проверки узлов, ограничения по стране, резервное копирование и управление версиями.

Комиссии оплачиваются только после подтверждения консолидации администратором. Автоматическая оплата комиссий доступна лишь для адреса настоящего заказа, если баланс выбранного разрешённого стейблкоина **строго больше 0,1**. В EVM пополняется только недостающая сумма; Solana использует фиксированный аккаунт для оплаты комиссий в SOL. При превышении одобренного лимита операция приостанавливается до ручной проверки.

У ресурсов дочернего сайта два разных пути трафика:

| Ресурс | Путь трафика |
| --- | --- |
| Подключённый узел дочернего сайта | Клиент соединяется напрямую с дочерним узлом; главный сайт не передаёт этот трафик. |
| Выходной IP дочернего сайта | Клиент соединяется с узлом главного сайта, а тот передаёт трафик через выход дочернего. |

## Область применения и ограничения

Текущие пакеты предназначены для полноценных Linux amd64 серверов с systemd. Не заявлены SLA, автоматическое переключение между сайтами или высокая доступность нескольких экземпляров. Скорость определяется прокси-ядром и сетевым маршрутом; Pro не ускоряет медленную линию. Статистика обновляется с интервалами. Изменения узлов, коэффициентов и протоколов активного тарифа синхронизируются на сервере; квота, срок действия и права в очереди сохраняют свои снимки. Клиенту со старой подпиской нужно обновить её.

Встроенный вариант с Trust Wallet Core — горячий кошелёк для небольших рабочих остатков. Шифрование не отделяет право подписи от скомпрометированного сервера; регулярно выводите средства. Импорт внешнего xpub позволяет наблюдать адреса без серверной подписи. Независимый аудит безопасности не заявлен. Публичные RPC и котировки могут быть недоступны; оценка комиссии не гарантирует конечную стоимость и не заменяет проверку в реальной сети.
