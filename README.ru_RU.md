Guangyue — панель для самостоятельного размещения прокси-сервисов и управления сетевыми ресурсами на Go и Vue 3. Подготовьте подходящий сервер и домен, который уже указывает на него, — и можно развернуть VLESS Reality/Vision и Hysteria 2, а затем управлять из панели подписками по тарифам, выходными IP, независимыми дочерними сайтами, заказами, обращениями и приёмом платежей.

Панель подойдёт операторам прокси-сервисов, которые начинают с одного сайта, администраторам, которым нужно централизованно управлять несколькими независимыми сайтами, и командам, выдающим участникам выходные IP. Lite предназначена для самостоятельной работы, Pro добавляет консоль главного сайта. Обе редакции устанавливаются одним интерактивным скриптом.

## Начало работы

### Перед установкой

- **Домен уже должен указывать на этот сервер, без проксирования через CDN.** В Cloudflare выберите «DNS only» и выключите оранжевое облако.
- Нужен **полноценный сервер Linux amd64 (x86_64) с systemd** и доступом root / sudo. Предварительная проверка принимает Debian 12/13 и Ubuntu 22.04/24.04; тесты нативной установки на виртуальных машинах пока охватывают Ubuntu 22.04/24.04. Допустимая ОС не означает, что проверены все конфигурации серверов.
- **Публичные TCP 443 и UDP 443 должны быть свободны и открыты** — и в группе безопасности облака, и в межсетевом экране хоста. Скрипт всегда использует порт 443 и не переносит существующий HTTPS-сервис; имеющийся Nginx на HTTP 80 можно оставить.
- **По умолчанию используется Docker, нативная установка доступна как вариант.** Docker пока публикует только IPv4: настройте лишь записи A, без AAAA; для IPv6 выберите нативную установку с двойным стеком. Docker требует Linux 5.4 или новее.
- Для начала рекомендуем 1 CPU / 1 GiB для Lite и 2 CPU / 2 GiB для Pro, а также запас места под образы, данные и резервные копии. Это рекомендация для установки, а не обещание числа одновременных пользователей или пропускной способности.

### Запуск установщика

Скопируйте весь блок в терминал сервера:

```bash
gy_install_file=$(mktemp)
curl --proto '=https' --proto-redir '=https' -fsSL \
  https://github.com/wudi000888-svg/guangyue-panel/releases/latest/download/install.sh \
  -o "$gy_install_file" && sudo bash "$gy_install_file"
rm -f "$gy_install_file"
```

Мастер предложит выбрать Lite или Pro, домен и способ развёртывания, проверит систему, ресурсы, DNS, порты и существующую конфигурацию Nginx / Docker, а затем покажет план установки для подтверждения. Компоненты и образы Docker берутся из выбранного выпуска и проверяются по его контрольным суммам; учётная запись в реестре образов не нужна. Сертификаты выпускаются и продлеваются автоматически через TLS-ALPN-01 на TCP 443.

После установки, следуя подсказке скрипта, прочитайте закрытый файл начальной учётной записи `/var/lib/guangyue/initial-owner.json`, войдите в панель, смените пароль администратора и проверьте VLESS и HY2 настоящим клиентом. При необходимости настройте регистрацию, публикацию тарифов и платёжные каналы; внешним платёжным и почтовым сервисам нужна ваша собственная рабочая конфигурация.

`--check` выполняет предварительную проверку только для чтения, `--resume` продолжает прерванную установку. Для существующих сайтов используйте [онлайн-обновление и откат](docs/UPDATES.md), а не новую установку поверх данных. Полные требования, восстановление после сбоев и ограничения развёртывания описаны в [руководстве по установке](docs/INSTALL.md).

## Lite или Pro

| | Lite | Pro |
| --- | --- | --- |
| Назначение по умолчанию | Независимый сайт; может быть и дочерним | Главный сайт, централизованно управляющий дочерними |
| База данных | SQLite | PostgreSQL |
| Кэш и задачи | Ограниченный кэш в процессе, постоянная очередь задач | Кэш Redis, постоянная очередь задач |
| Функции сайта | Узлы, пул IP, тарифы, пользователи, заказы и обращения | То же, что в Lite, плюс централизованное управление |
| Подключение | Создаёт токен дочернего сайта для импорта на главном | Вставьте токен дочернего сайта, чтобы подключить его |
| Установка | Docker / нативный systemd | Docker / нативный systemd |

Для установки не нужны ни файл регистрации, ни заранее созданные группы сайтов. **Дочерний сайт создаёт токен, главный сайт Pro его вставляет.** Токен может иметь срок действия или оставаться действительным до отзыва. Подключённый дочерний сайт сохраняет локальных администраторов, учётные записи, базу данных и собственные службы; доступ можно отозвать. У дочернего сайта, впервые переданного под управление, модуль платежей по умолчанию выключен, но локальный администратор может включить его. Подробнее — в разделах [редакции](docs/EDITIONS.md) и [управление сайтами](docs/BUSINESS-SITES.md).

### Тариф определяет, какими узлами может пользоваться участник

Администратор выбирает для тарифа группы локальных, дочерних или публичных узлов либо конкретные узлы внутри группы. Участник видит свой текущий тариф, оставшиеся время и объём, подписку и клиенты, и ему не нужно разбираться в группах узлов и внутренних правилах смешанных подписок.

При покупке другого тарифа оставшийся срок текущего приостанавливается и возобновляется в порядке очереди прав. Возвраты проверяет администратор: активный тариф возвращается пропорционально оставшемуся объёму или времени, заказы из очереди пока возвращают исходную сумму заказа, а порядок восстановления остальных прав сохраняется. Точные правила — в разделах [тарифы](docs/PLANS.md) и [заказы и возвраты](docs/COMMERCE_EN.md). Изменения узлов, коэффициентов и протоколов активного тарифа синхронизируются с правами доступа на сервере; объём, срок действия и тарифы в очереди сохраняют свой снимок. Подписку, закэшированную клиентом, всё равно нужно обновить.

### Узлы и IP дочернего сайта — два разных пути

- **Смонтированные узлы дочернего сайта:** клиент подключается напрямую к узлу дочернего сайта, трафик не проходит через главный.
- **Выходные IP дочернего сайта:** клиент подключается к узлу главного сайта, а главный пересылает трафик через выходной IP дочернего.

Эти два типа ресурсов управляются отдельно и помечаются по источнику. Когда общий бюджет дочернего сайта исчерпан, доступ приостанавливается согласно настройкам и восстанавливается после паузы; членство в группах узлов сохраняется. Порядок настройки описан в разделе [монтирование узлов и бюджеты](docs/NODE_MOUNTS.md).

### Приём криптовалюты и кошельки

Когда пользователь выбирает оплату криптовалютой, заказу выделяется собственный адрес, который сохраняется навсегда. Автоматический приём и сбор средств сейчас охватывают поддерживаемые активы USDT / USDC в сетях Ethereum, BNB Smart Chain, Plasma и Solana согласно разрешённому списку контрактов или mint; наличие настроек L2 не означает поддержку автоматических расчётов и сбора в ней.

Запросы баланса и Gas выполняются только для чтения. **Комиссии оплачиваются только после того, как администратор подтвердит сбор средств.** Автоматическая поддержка комиссий применяется только к настоящим адресам заказов, где баланс выбранного стейблкоина из разрешённого списка строго больше 0,1. В EVM доплачивается лишь недостающая сумма; в Solana комиссии оплачиваются с фиксированного адреса с SOL. Если исходно одобренный предел комиссии будет превышен, операция приостанавливается для ручной проверки. Подробности и различия между сетями — в разделах [управление кошельками](docs/CRYPTO_WALLETS.md) и [приём и сбор средств по заказам](docs/CRYPTO_TREASURY.md).

Встроенный горячий кошелёк предназначен для небольших операционных остатков. Мнемоническая фраза хранится в зашифрованном виде, но право подписи остаётся на том же сервере: сделайте закрытую резервную копию и регулярно выводите средства. Внешний EVM xpub подходит для получения адресов и запросов балансов, а переводы выполняются из внешнего кошелька; права подписи у сервера при этом нет.

## Область применения и ограничения

- Напрямую предоставляются входящие протоколы **VLESS Reality/Vision и Hysteria 2**. Импортируемые форматы источников зависят от парсера и Mihomo и не добавляют одноимённых нативных входов.
- Сейчас развёртывание — это один контроллер на сайт. Не обещаются высокая доступность с несколькими ведущими узлами для одного сайта, изоляция арендаторов на уровне организаций, SLA или независимый аудит безопасности. База данных и кэш Pro не ускорят сетевой маршрут, который перегружен сам по себе.
- CI включает изолированную установку на Linux, восстановление при обновлении и проверку протоколов. Это не отчёт о производительности в крупном продакшене и не приёмка ваших торговых настроек или транзакций в основной сети. Перед запуском проверьте настоящих клиентов, резервные копии, почту и платёжные сценарии.
- Источники RPC, котировок и проверки качества могут ограничивать запросы или быть недоступны. Неизвестный результат никогда не считается нулевой комиссией, а доступность публичной страницы не означает, что учётные записи, воспроизведение, платежи или региональные сервисы разблокированы.
- В репозитории есть **описание проекта на 7 языках**; интерфейс панели пока поддерживает **упрощённый китайский и английский**. Подробные руководства в основном на китайском, часть — на английском; переведённое описание не означает, что интерфейс и руководства локализованы на этот язык.
